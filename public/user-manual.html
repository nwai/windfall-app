Windfall App

User Manual  ·  Version 1.1  ·  May 2026

Overview

The Windfall App is an analytical tool for Weekly Windfall lottery number analysis and candidate generation. It provides:

  • Candidate set generation using configurable strategies and constraints
  • Multi-signal scoring of each candidate (Conv, IDM, Stage IDM, Rdy, Win, Nrr, NS)
  • Monthly frequency analysis of drawn numbers
  • Zone pattern analysis, temperature transitions, and Monte Carlo simulation
  • DGA (Draw-Grid Analysis) visualisation
  • Historical prize back-testing

Getting Started

Panel startup and help

Panels start closed when Windfall loads, including Guided Setup, generation panels and the DGA subpanels. Previously open panels are not restored. Open a panel when you need it; navigation shortcuts and deliberate actions such as New Prediction can still open the relevant area.

The ? button beside a panel title opens a keyboard- and touch-accessible overview without opening the panel or running its analysis. It explains the purpose, startup state, effects on selections and generation, data scope, reliability limits, and shared evidence sources where registered. Use Open panel to inspect the actual controls and current audit results, or User manual for more detail. Escape or Close returns to the help button.

Closed does not mean Off. Opening or closing a panel never resets saved settings, forced inclusions, exclusions or generation rules. Check Active Setup Summary and Trace for what is active. Help describes implemented methods and limitations; it does not invent a success rate, run a new backtest, or label heuristic support as a calibrated probability. Live audit results remain in their owning panel so the history scope, sample size and comparison baseline stay visible together.

Section title colours: History, Signals, Validation, Generation, DGA and Patterns each have a contrasting heading colour, shared by that section's panel titles and navigation label. These colours are location cues, not warnings, confidence ratings or evidence of predictive quality. The written section names remain visible. Main/supplementary number colours and diagnostic legends keep their existing meanings.

Guided Setup

Guided Setup is the compact checklist near the top of the app, directly below Data provenance. It is a navigation and review aid only: it does not change generation, ranking, filters, forced inclusions, forced exclusions, or prediction scoring.

The guide is split into two lanes:

  • Pre-draw path — the order to follow before the next result is known.
  • After the draw happens — the work to do only after the official result has been entered.

Before the draw

  1. Confirm draw history. Load or update the real draw CSV, then check the latest date shown in Draw History Manager.
  2. Set WFMQYH. Choose the active evidence window. Many tactical panels and generation weights read this window, so confirm the draw count and date range before interpreting results.
  3. Review evidence panels. Inspect Signals and Validation panels for current evidence. Treat diagnostic labels as evidence, not guaranteed predictions.
  4. Choose inclusions and exclusions. Use User Selected Numbers and other selectable tables only after checking active exclusions, forced inclusions, and conflict warnings.
  5. Review generation constraints. Open Candidate Generation Setup and check odd/even ratios, Stage-Match, MiAN, latest-draw rules, drought quotas, hard filters, and active weighting. The guide summarizes active constraints so you can spot an accidental setting quickly.
  6. Generate and inspect candidates. Generate rows, then use the candidate table, Portfolio Compression, Paste-Weighted Generator, Selection Insights, and DGA as needed.
  7. Save a prediction before the draw. Prediction Journal captures your setup state and hypothesis before the result exists, which keeps later scorecards honest.

After the draw has happened

  1. Enter the actual draw. Add the official result to Draw History Manager and save it to the CSV.
  2. Prize check in Generated Candidates. Use Manual Prize Check after the real result is known. This belongs in the post-draw inspection path, not the pre-draw setup path.
  3. Score saved predictions. Use Prediction Journal & Scorecard, including Compare active entries to latest draw, to record hit, partial, miss, and replay-prize evidence.
  4. Record lessons learned. Use Research Diary for recurring observations such as draw ordinal, weekday, DGA constellation, drought behaviour, or SDE1/HC3 context.
Truthfulness note: Guided Setup is deliberately not a wizard that makes decisions for you. It shows the order of work and links to the relevant panels, while the underlying panels remain responsible for their own evidence, constraints, and diagnostics.

Loading Draw History

The app requires draw history data to power analysis, scoring, simulation, and candidate generation. Use the Draw History Manager panel near the top of the app to load, maintain, and verify your history.

  1. Open Draw History Manager and click Select CSV target (or Change CSV target).
  2. Choose your history file (typically windfall_history_lottolyzer.csv).
  3. The target is remembered for saves and future startup where the browser supports persistent file handles. To load its rows immediately, press Reload CSV target in the status strip near the top of Windfall.

You can also load history by using Import Draws (CSV/JSON) from the same Draw History section. This is useful when you receive draw history from another tool or from a saved export.

Remembered CSV target at startup

Choose the target once after installing this feature; earlier versions did not retain the file handle. Windfall stores that handle in IndexedDB for the exact browser address and profile. On startup, it reads the selected file when read permission is still granted, restores it as the shared save target, validates its rows, and loads its history. At equal latest dates, the actual file takes precedence over cached rows so external corrections are visible. If the browser holds strictly newer valid results than the file, Windfall keeps those results and explicitly reports that the CSV needs syncing. Startup never writes to the file.

If permission has expired, the top-of-app CSV target status offers Reconnect CSV. That explicit action can ask the browser to restore read access. A missing, unreadable or invalid target is not silently presented as loaded: the status explains the problem and identifies the bundled CSV or saved browser history used as fallback. No simulated replacement is created by this preload. Cancelling or denying reconnection leaves loaded history unchanged. Write permission is requested only when you explicitly save a result or correction.

Change CSV target opens the picker for a different file. Forget CSV target removes only the remembered file connection, not the file or loaded draws. Changing hostname, port, browser profile or device uses a different local store. Browsers without the file-picker API cannot automatically reopen a local file; ordinary CSV import and downloaded saves remain available.

History table and terminal composition

Mains are red and supplementary numbers are green, matching their role colours in the Prediction Journal and DGA. The labelled columns identify each role even without colour.

The scrollable history table uses right-aligned columns and sticky headers, with the newest draw first. It shows the active WFMQYH rows: Date, Mains (6), Supps (2), OGA, Odd/Even, Terminal shape and Terminal runs. Shape and runs describe all eight numbers using the same calculations as Draw Composition Quotas. For example, the recorded 10/9/26 draw 28,33,36,15,40,18 | 44,4 has shape 2+2+1+1+1+1 and exact maximal run 3-4-5-6. Two separate runs are shown separately; a longer run is never split into overlapping sub-runs. None means a valid eight-number draw has no consecutive terminal run of length two or more. A dash means a diagnostic is unavailable. Simulated rows are labelled and do not receive real-history OGA scores.

Saved draw-history CSV files retain the original nine data columns and append terminal_shape and terminal_runs. Separate runs share one CSV cell, separated by ; . These are deterministic descriptions of the recorded numbers, not forecasts or additional drawn numbers. Saving recalculates them from the six mains and two supps rather than trusting imported diagnostic text. Original nine-column history files remain importable; the extra columns are added on save. Invalid official number rows are rejected, and simulated rows are omitted from official CSV saves.

Display versus file: OGA and Odd/Even were already calculated in the in-app preview; they were not stored in the source CSV. OGA still belongs to the active real-history view, because its value depends on the reference history. CSV is plain data and cannot store alignment; right alignment and sticky headings belong to the app's table or a spreadsheet's formatting.

Manual entry and maintenance buttons

  • Add draw opens a blank entry form in Draw History Manager → Draw history source.
  • Edit latest draw opens the newest saved result with its numbers already filled in. Use Draw to correct to choose an older result. Correct the mains or supps, check the official result, then press Save correction. A correction replaces that date rather than creating another draw.
  • Check against The Lott compares the date and the six mains and two supplementary numbers against The Lott's public Weekday Windfall results feed. Order within each group is ignored; swapping a main and a supp is not accepted as a match. A mismatch shows the official numbers and prevents saving. Use official numbers fills the entry form only; check again before saving.
  • Save draw or Save correction writes the checked result to the selected CSV (or creates a download when direct writes are unavailable). Cancelling the file picker leaves loaded history unchanged. A downloaded CSV must replace your source file before future startup loads can see the change.
  • Select CSV target chooses the destination file; Change CSV target changes that destination. This does not itself import its rows.

Verification limits: the checker requests the latest 50 results from the official service. An older result, an unpublished draw, a connection failure, a malformed response or conflicting official rows is not verified. No CSV, simulated, cached or third-party fallback is treated as an official match. If automated verification is unavailable, open The Lott's official results, check the date and both number groups yourself, and explicitly acknowledge saving without automated verification. The app does not claim that this manual acknowledgement is an automated match. Editing any date or number invalidates the previous check. Imported history is not certified merely because its format checks pass.

Duplicate protection: the app now blocks saving an exact duplicate draw and also blocks saving a second, different result for a date that already exists. This prevents the most common manual-entry mistakes before they reach your history file.
Safari users: If the File System Access API is not available, a standard file picker will appear automatically as a fallback.

WFMQYH Window

WFMQYH is the active draw-history window used by many evidence panels and generation weights. The shortcuts are designed around draw counts rather than calendar labels: Weekly uses 3 draws, Fortnight uses 6 draws, Month uses 13 draws, Quarter uses 36 draws, and Year uses 156 draws.

Why Month is 13 draws: although some calendar months contain 12 or 14 draw dates, 13-draw months are the most common practical monthly shape in the loaded Windfall history. The Month shortcut therefore uses 13 draws as the standard month-like evidence window. Panels that perform calendar-month analysis, such as Monthly Draws Summary and Stage IDM, still calculate the actual expected draw count for the working month where that matters.

History Scopes

Windfall now separates history scopes so diagnostics do not quietly mix short tactical windows with long-run baseline evidence.

  • Current WFMQYH window means the active selected draw window. Tactical panels and generation-weight views use this when the user is intentionally asking, “what does the current selected window say?”
  • Real all history means the loaded real draw history after simulated or fallback rows have been excluded.
  • Windfall baseline history means real all history with the opening partial month removed when that first month is incomplete. This is used for baseline and validation-style panels such as Survival Analyzer, Temperature Transition Diagnostics, Most Likely NOT Drawn, and MLND Backtest Validation.
Truthfulness note: Monte Carlo remains a current-window weighting tool. It is not an all-history calibration panel, and its label shows the WFMQYH scope it is using. It runs independently from Survival Analyzer selections: Survival's selected-number state is not passed into Monte Carlo.

Monte Carlo: What Is Applied

Model WF-MC-2 starts with Trend Bias OFF. Each eligible number receives its observed count plus 0.5 before normalization. This fixed smoothing prevents an unseen number from being silently excluded. Only explicit active exclusions get zero weight.

When enabled, Trend Bias uses exp(3 × (recent rate − comparison rate)), comparing the latest 6 and 13 draws with their actual available denominators. It is a heuristic, not a calibrated likelihood. Base and Biased percentages are normalized sampling weights; Sim is the fraction of simulated sets containing that number. These are different quantities.

A run records its completed simulation count and random seed. Editing Runs does not change an earlier result's denominator. Changing evidence, exclusions or weighting marks that result stale until rerun. Fewer than eight eligible numbers blocks an eight-number simulation. Generator forced numbers are shown for context only; Monte Carlo does not force them or use Survival's selections.

Survival Analysis

Survival Analysis estimates number-level drought return behaviour using a discrete-time drought hazard model with Bayesian shrinkage. In the main app it uses Windfall baseline history, not the active WFMQYH window, so its baseline is not distorted by very small tactical windows.

Monthly Transition Context columns

The Survival table also shows observe-only monthly movement context from the Monthly Bucket Transition Lab. These columns help compare survival drought evidence with the current monthly bucket state, but they do not change Survival ranking, probabilities, selections, or generation weights.

ColumnMeaning

Honesty note: Monthly Transition Context is evidence context, not a calibrated probability. It is deliberately observe-only until walk-forward testing shows whether it improves Survival ranking.

Advanced Survival & State Diagnostics

This panel now contains descriptive state and recurrent-gap evidence only. The former churn classifier, return predictor, Cox top-picks, and cross-model consensus were removed from the active app because they did not have comparable temporally labelled out-of-sample validation.

  • Multi-State (Active → Churned → Returned) counts current states and historical transitions under the displayed inactivity threshold. It is a state summary, not a future-state probability.
  • Recurrent Gap Dispersion Diagnostic reports appearances, completed gaps, mean/median gap, gap IQR, coefficient of variation, current drought, and current drought divided by historical median gap.
  • Drought / median above 1 means the current drought is longer than that number's median completed gap. It is descriptive maturity, not evidence that a return is imminent.
Removed false precision: the old “gamma frailty” percentage was calculated from gap variance without fitting a valid frailty distribution. It has been removed and is not available as a next-draw probability.

Temperature Transition Diagnostics

Temperature Transition Diagnostics compares how number temperature states move through history. It is diagnostic evidence only: it does not force inclusions, force exclusions, change generation weights, or claim a calibrated next-draw probability.

Volcanic Precursor Advisor

The Volcanic Precursor Advisor asks: when a number became Volcanic in a recorded draw, what temperature state was that same number in immediately before the hit? The advisor shows Recency, EMA, and Hybrid side by side so you can compare whether the same precursor state appears across different temperature metrics.

  • Prior temp is the temperature color/name after draw t-1, immediately before a number was drawn at draw t.
  • Count is how many Volcanic hits had that prior temperature state.
  • Observed rate is Volcanic hits / all prior-state trials. It is an empirical rate, not a guarantee.
  • Avg hit gap is the average number of draws between the number's prior hit and the Volcanic hit being counted.
  • Since hit is how many draws have passed since the latest Volcanic hit that came from that prior temperature state.
  • Learnt compares recent transition evidence with the full selected scope and labels it as Recently rising, Recently falling, Stable, or Thin sample. This updates when new real draws are added.

The advisor includes a Baseline / WFMQYH scope switch. Baseline uses Windfall baseline history; WFMQYH uses the active filtered window. WFMQYH is useful for tactical inspection, but short windows can produce thin or noisy samples.

Truthfulness note: “Volcanic” in this advisor means the number was drawn in the next recorded draw under that temperature metric. The advisor is a precursor diagnostic, not a prediction guide yet.

Number Trends Table

The Number Trends Table shows the 45 numbers in nine compact blocks of five numbers. Each row is designed for quick scanning: the number pill, direction arrow, and Δ 3→13 value share the same colour so the recent movement signal is visible at a glance.

Choose a local history source

History source switches between WFMQYH (the default, using the active global draw window or range) and All history (all loaded real draws, including the opening partial month, not the baseline-month slice). The source line shows the actual draw count and date range. Simulated and malformed rows are ignored. An empty source shows unavailable evidence rather than substituting the other source.

This is local to Number Trends: it changes this panel's counts, direction arrows and selected-number chart, not global WFMQYH, generation settings, other panels' trend inputs, or shared forced inclusions/exclusions. Changing WFMQYH still refreshes the WFMQYH view; new history refreshes All history. Short-window counts may be identical in both views if both include the same newest draws.

Live drought shortlist flags

Every number row has two read-only flags: Strict Yes/No and Empirical Yes/No. Red Strict Yes means the number is on the current top-eight Strict drought 6+ shortlist; blue Empirical Yes means it is on the current top-eight Empirical hazard shortlist. A number can have both flags set to Yes. No means it is not on that shortlist, not that it can never be drawn. n/a means the shortlist data is unavailable. Strict No can still describe a number with a six-draw drought that did not rank inside the top eight.

These flags mirror Drought-break shortlist, not a new ranking calculated from Number Trends. Strict uses full real-history drought context; Empirical uses the active global WFMQYH evidence. Changing Number Trends' local History source leaves the flags unchanged. Updating real history or global WFMQYH refreshes the underlying lists. Membership is shown before generation exclusions: a listed number can retain Yes while its row is marked Excluded and disabled. The flags do not select numbers, activate a boost, alter a quota, or claim a predictive advantage.

What the draw-window counts mean

  • 3D, 6D, 9D, 13D, and 15D count how many of the latest 3, 6, 9, 13, or 15 draws contained that number.
  • 36D and 156D count across up to the newest 36 or 156 draws in the chosen source. Each D count is capped by the source's available history.
  • All totals the chosen source: the active window in WFMQYH mode, or every loaded real draw in All history mode. It does not always mean the complete CSV.
  • A number is counted once per draw, whether it is a main or supplementary number. Draws are ordered by date before taking the newest windows.

What the arrow and + / - number mean

The direction arrow compares the number's latest-week rate with its typical-month rate:

(3D count / 3 × 100) - (13D count / 13 × 100)

That formula assumes at least 13 real draws. With fewer, each denominator is the actual available count, shown below the chart. For example, with six draws, it is (3D count / 3 × 100) - (13D count / 6 × 100). With two draws, both rates use those same two draws, so their difference is zero. This prevents missing history being counted as non-appearances.

  • Up arrow — the number's latest 3-draw rate is meaningfully higher than its latest 13-draw rate.
  • Down arrow — the number's latest 3-draw rate is meaningfully lower than its latest 13-draw rate.
  • Flat arrow — the difference is small enough to treat as broadly stable.
  • The + or - value beside the arrow is the percentage-point difference between those two rates. For example, if a number appears in 2 of the last 3 draws and 3 of the last 13 draws, the calculation is 66.7% - 23.1% = +43.6. A negative value means the latest 3-draw rate is below the 13-draw rate.
Truthfulness note: this is a recent-vs-broader-history diagnostic, not a calibrated probability or guarantee that a number is due to appear. Use it as movement evidence alongside the other panels.

Movement Replay

Open Movement Replay near the top of Number Trends to follow one number through successive recorded draws. Model version NTMR-1 means Number Trends Movement Replay version 1. It starts closed and uses this panel's local History source. Inspect number is independent: inspecting an excluded or unselected number does not select it, force it into candidates, change generation, or add an independent evidence vote.

The value is not a hit/miss indicator. It is 100 × (latest-three appearance rate - latest-thirteen appearance rate), using only draws through the date shown. For example, one appearance in the latest three and three in the latest thirteen gives 100 × (1/3 - 3/13) = +10.3 pp, even if the number missed the most recent draw. A number can also hit the latest draw while its value remains negative. Changes can occur simply because an old hit leaves a rolling window. Flat includes -5.5 to +5.5 pp; Up is above +5.5 and Down is below -5.5.

  • Timeline: oldest left, newest right. Red markers mean main hits; green markers mean supplementary hits. Both count equally in the score. Unmarked positions were not drawn. The inspection slider, usable by keyboard, shows the exact date, score, component counts and hit role; Latest returns to the newest position.
  • Timeline draws: Latest 60, Latest 120, or All in source changes only the chart and newest-first scrollable log. The ranges, state-duration table and next-draw comparison still use the complete selected source.
  • Current value: the latest score and actual draw denominators. Positions with fewer than thirteen draws use the available counts and are marked warm-up. The first twelve positions are excluded from full-window ranges, state durations and next-draw comparisons. Selecting only thirteen WFMQYH draws leaves one full-window state and no settled full-window next-draw trial.
  • Observed lowest / highest: the number's measured extremes in this source once thirteen draws were available. The displayed date is the first occurrence of that extreme. These are not unbreakable floors or ceilings.
  • Typical range, P10-P90: the 10th to 90th percentiles of full-window values, using linear interpolation. It describes the middle of the recorded distribution, not a confidence interval or prediction range.
  • Mathematical limits: with thirteen draws, -76.9 to +76.9 pp. The latest three are part of the thirteen, so the two rates cannot vary independently. With a shorter source the limit is ±100 × (1 - recent draw count / comparison draw count); with three or fewer draws the two rates coincide and the difference is zero.
  • Time in each state: number of full-window positions, share and longest uninterrupted run of recorded Up, Flat or Down states. Current run counts full-window states only, not warm-up. A missing scheduled draw breaks a run rather than assuming its state.

What followed similar values? compares the same number's score after draw t with its actual appearance, main or supplementary, in the next scheduled draw t+1. Seven fixed score bands are used; their boundaries do not adapt to which bands performed best. Current marks the latest full-window score's band. Hits / trials are raw counts; Observed rate is hits divided by trials; Vs 8/45 is the percentage-point difference from the neutral 17.8% per-number reference. Zero trials shows n/a, not a fabricated rate. Fewer than thirty trials is labelled Thin; Descriptive does not mean validated.

The replay omits simulated, malformed, off-schedule and all rows sharing a duplicate date, with omission counts shown. Its stricter qualification can therefore differ from Number Trends counts above. It does not invent missing draws. A missing next scheduled date is not scored as a miss, and the latest position remains unscored until the next result exists in the chosen source. This is a no-lookahead historical association check, not a calibrated next-draw probability: rolling windows overlap, inspecting many numbers can uncover chance patterns, and no generation benefit is claimed. It refreshes when real history or the chosen scope changes; it does not train a generation model.

The older selected-number chart below the number blocks remains a draw-window count comparison (3D, 6D, 9D and so on), not a dated timeline. Use Movement Replay for actual chronological movement.

Number Trends sits immediately below WFMQYH. Clicking an available number row marks or unmarks a Number Trends forced inclusion. Shared forced inclusions, including Drought-break selections, also appear selected. A row owned only by another panel is locked here: release it at that source, or use Active Setup Summary's source-removal controls. If more than one source forces the number, release every source. Active exclusions disable the affected rows. These selection states do not change the historical trend counts or automatically activate selected-number boosting.

Trend Ratio Diagnostics

Trend Ratio Diagnostics records the observed Up / Down / Flat trend composition of historical draws. Each ratio is written as U-D-F, where the three numbers count how many of the eight drawn values were classified as Up, Down, or Flat at that point in history.

Scope and timing

  • The ratio uses mains + supplementary numbers, so every valid ratio totals 8.
  • For each historical draw, the app classifies trend state using only values available before that draw. The trend scale also uses only the history available at that point, which protects the diagnostic from lookahead leakage.
  • The table includes all 45 possible U/D/F ratios, even when a ratio has zero observed historical occurrences in the active WFMQYH window.

What z means

The z column compares the observed count for each ratio with a neutral finite-population reference. For each eligible historical draw, the app first counts how many of the 45 numbers were Up, Down, or Flat before that draw, then asks how often an 8-number draw sampled without replacement from that classified pool would produce each ratio. A larger absolute z value means that ratio appeared more or less often than this neutral reference would expect.

Truthfulness note: z is a diagnostic, not a calibrated probability. It is useful for spotting unusual historical structure, but it does not guarantee that a ratio is due or likely in the next draw.

What the Add button does

The Add button toggles a ratio into the active generation filter. The default state is off: when no ratios are selected, all trend ratios are allowed. Click Add once to turn a ratio on; click the same button again when it shows On to remove that ratio and return it to the off/default state.

When one or more ratios are selected, candidate generation rejects candidates whose current Up / Down / Flat composition does not match one of the selected ratios. Trace output reports the active selected ratios, lookback, threshold, historical coverage, and trend-ratio rejection count.

Smart History Review

Under the Draw History Manager, the app includes a Smart History Review panel. This is designed to help you correct human-made history problems without editing CSV files by hand.

What it detects

  • Draw date needs review — an invalid date or a real draw dated outside Monday, Wednesday or Friday. Manual entry, date edits and CSV saving reject these dates. Imported or cached rows remain visible for correction; the app does not guess a replacement date. CSV saving also rejects duplicate draw dates.
  • Scheduled dates absent from loaded history — a Monday, Wednesday or Friday between the first and last recorded dates has no result. Check the official source and add the missing result. Dates before the first record or after the last record are not treated as gaps.
  • Exact duplicate draw — the same date and the same 6 main + 2 supplementary numbers appear more than once.
  • Conflicting entries for one draw date — two or more rows share the same draw date but contain different numbers.
  • Same number set appears on multiple dates — the exact same numbers appear on more than one date. This can happen naturally, but it is rare enough to review for copy/paste mistakes.

Available review actions

  • Remove exact duplicates — safely removes repeated copies of identical rows while keeping the first occurrence.
  • Keep this version — when two rows share a date, keep the correct one and remove the others for that date.
  • Edit — opens an inline editor so you can correct the date and/or numbers directly inside the app.
  • Delete — removes the selected row from the current loaded history.
Important: if Smart History Review shows same-date conflicts, review them before relying on analysis panels. Two different results on the same date will distort bucket counts, DGA columns, and any logic that depends on recent history.

If the default CSV corrects weekday errors in an equally recent cache with exactly the same number of draws and main/supp number sets, startup uses the corrected CSV and records the decision in Trace. Newer cached results are never discarded for this date-only refresh. Editing a date to one already occupied by another result is blocked.

Typical correction workflow

  1. Load or import your draw history.
  2. Use Remove exact duplicates first if offered.
  3. Review each same-date conflict and either Keep this version or Edit the mistaken row.
  4. Review repeated-number warnings on different dates to rule out copy/paste errors.

Final survivor selection

When Overgen × creates a larger accepted pool than the requested Count, Windfall must choose which accepted rows survive into the visible table. PNUaRW45 / RwR45 Random Coverage Mode

PNUaRW45 is a special random coverage mode in the main Generated Candidates panel. The toggle is labelled RwR45.

  • When OFF — the normal candidate generator is used and the Count input controls how many candidates are requested.
  • When ON — the normal Count value is ignored and the app creates exactly 7 candidates.
  • The generator shuffles numbers 1–45 uniformly at random.
  • Hard exclusions are removed before random fill. Forced inclusions are seeded into every candidate, matching the normal generator’s forced-number contract.
  • If Use counts when constructing candidates is ON in Monthly Draws Summary, PNUaRW45 checks every 8-number row against those Acceptance Needs bucket minimums.
  • When no hard constraints are active, the first 42 numbers are split into seven non-overlapping six-number main sets, so main numbers are globally without replacement across the 7 candidates.
  • When forced inclusions, exclusions, or Acceptance Needs counts are active, global-without-replacement applies to the remaining non-forced main filler numbers where possible. If the active constraints make the original strict partition impossible, Windfall uses a row-safe random fallback that still avoids duplicates inside each candidate and still respects exclusions and the active bucket minimums.
  • With no hard constraints, the remaining 3 numbers become the supplementary pool. Under constraints, the preferred supplementary pool is the unused eligible remainder, with row-safe fallback if needed.
Truthfulness note: PNUaRW45 is random coverage, not a prediction, score, or evidence-weighted strategy. While RwR45 is ON, Count, odd/even quotas, scoring influence, and most evidence filters are bypassed. Hard forced inclusions, hard exclusions, MiAN hard exclusions where active, and Monthly Draws Summary Acceptance Needs counts when Use counts is ON are honored before display.
The 3 leftover numbers cannot fill all 14 supplementary positions globally without reuse. In unconstrained RwR45, Windfall therefore keeps the main numbers strictly global-without-replacement and reuses the 3-number supplementary pool row by row.

Shapes and runs vary: RwR45 does not always produce the same terminal repetition shape or exact terminal runs. Random partitions can differ each time, although forced numbers and bucket requirements can make some compositions recur. If all eight numbers are forced, their shape and runs are necessarily fixed. Draw Composition Quotas also reports the actual odd/even distribution of the last RwR45 output separately from your selected quota settings.

Last RwR45 output: after generation, expand the composition output above Generate to inspect the actual final rows: odd/even, repetition shape, separate exact terminal runs, single/two-digit counts and bucket origins across all eight numbers. Terminal Repetition Shapes and Terminal Run Quotas show a separate Last RwR45 rows column. Ending Digit Limits shows actual number occurrences and rows containing each ending; Monthly Draws Summary shows each row's bucket-origin mix. These readouts do not select quotas, alter Acceptance Needs, invent historical observations or enable boosts. Bucket origins and planning context are frozen at generation time. The most recent RwR45 readout remains labelled as such even if you later change modes or load history. Separate runs can occur in the same row, so their occurrence counts can overlap. Enabled readiness filters and session deduplication can leave fewer than seven final rows.

Stage IDM vs Monthly Acceptance Needs

The paste-weighted generator has two separate monthly-bucket controls because they answer different questions:

  • Stage IDM bucket mix is an exact six-main composition filter. Its default is derived from the Stage IDM target and reconciled to six mains because paste-weighted candidates do not include supplementary numbers.
  • Monthly Acceptance Needs uses the literal minimum counts selected in Monthly Draws Summary. For example, 0x≥2 · 1x≥1 means every accepted paste-weighted candidate must include at least two undrawn numbers and at least one 1x number.

Monthly Acceptance Needs is not rescaled. If the selected requirements total more than six, the paste-weighted generator shows an impossible-for-mains-only warning instead of silently changing the user's selected needs.

Honesty note: Stage IDM is a descriptive stage-alignment filter. Monthly Acceptance Needs is a literal user-selected requirement filter. Neither should be read as a calibrated next-draw probability.

Portfolio Compression / 12-Game Distiller

The Portfolio Compression / 12-Game Distiller helps reduce a group of generated or pasted rows into a six-number core plus alternates. It starts with count compression: numbers that appear more often across the supplied portfolio rows rise to the top.

This panel is best used as a decision-support layer. It helps answer: "if I already have a portfolio of candidate rows, which numbers are carrying the most repeated support across that portfolio?" It does not prove that those six numbers will be drawn.

Rows counted is every pasted or loaded row containing at least one valid number. Valid game rows is stricter: rows must contain exactly 6 or 8 unique in-range numbers. Rows needing review are still counted, but the panel flags them so malformed input cannot pass silently.

Load current generated candidates loads generated rows from the main and paste-weighted generators. Supplementary numbers are included when the source provides them; paste-weighted rows are usually mains only.

Optional evidence columns are observe-only and labelled by scope. For example, hot/cold uses mains + supps, while adjacent combos and window shape are mains-only diagnostics. These columns do not change the top-six core.

Core-and-Hedge Portfolio

Core-and-Hedge Portfolio is an experimental arrangement tool for concentrating candidate rows you already supplied. It is not a separate prediction engine. It identifies a shared six-number idea, then constructs controlled hedge games around that idea. It never introduces a number that was absent from the valid source rows, uses no known winning result, and does not change the main generator.

  • Primary game: the six numbers appearing in the most valid source rows. Numeric order breaks an exact count tie.
  • Hedge games: each retains either four or five primary numbers, according to the selector, and fills the remaining positions from the highest-count alternates.
  • Portfolio games: controls the total number of concentrated lines, including the primary game.
  • New coverage: alternate numbers introduced to the concentrated output for the first time on that row.
How the portfolio is constructed
  1. Validate the source rows. Only rows containing exactly six or eight unique numbers from 1 to 45 enter the concentration calculation. Imperfect rows remain visible for review but are excluded.
  2. Count number appearances. Each number receives one observed count for every valid source row containing it. In an eight-number row, all eight numbers are treated equally; this calculation does not distinguish its mains from its supplementaries.
  3. Build the primary game. The six highest-count numbers form the primary game. A lower number wins only when appearance counts are exactly tied; this is a reproducible tie-break, not evidence that lower numbers are better.
  4. Build the alternate pool. After removing the primary six, the next 12 highest-count numbers form the internal alternate pool, or fewer when fewer supported numbers are available.
  5. Enumerate the possible hedges. With 4 of 6 retained and a full 12-number alternate pool, Windfall examines C(6,4) x C(12,2) = 990 possible hedge games. With 5 of 6 retained, it examines C(6,5) x C(12,1) = 72. This is deterministic enumeration, not random sampling.
  6. Select the displayed hedge games. While an uncovered alternate remains available, Windfall first considers games that introduce at least one new alternate. Those eligible games are then ordered by higher row support, higher pair support, lower overlap with earlier hedge games, and finally numeric order.

Choosing 4 of 6 gives the portfolio broader alternate coverage. Choosing 5 of 6 keeps each hedge closer to the primary game. If there are not enough alternates or unique arrangements to build the requested number of games, Windfall returns fewer games and explains why.

Recommended workflow

  1. Use 10,000 Monte Carlo histories for serious reading.
  2. Run several training-window settings, such as 24, 36, 50, 75, and 100.
  3. Look for stability across settings, not one lucky result.
  4. Prefer results where the structural-state strategy has a positive prize delta, higher mean matches, higher 3+ hit rate, lower or comparable drawdown, and a low p-value.

Signal Confluence / Number Consensus Ledger

Signal Confluence / Number Consensus Ledger is primarily an observe-only Validation panel. It answers a practical question: which numbers are being mentioned by several registered Windfall evidence groups at the same time?

The fixed WF-EVIDENCE-1.0.0 portfolio rule counts at most one bounded contribution from each independence group. The strongest eligible mention wins inside a group, then those bounded group values are added equally. Aggregators, consumer output and user state remain visible as context but cannot add another vote. The included families and weights are fixed before the target draw; they are not chosen after seeing which numbers won.

By default the panel does not generate candidates or claim that agreement is proof. If the user deliberately clicks a directly supported number pill, that number becomes a Signal Confluence forced inclusion for candidate generation. A context-only number cannot be forced from this panel.

Choosing which rows to see

  • Evidence/context is the default. It hides ordinary empty rows, while retaining direct evidence, context-only mentions, and any selected, forced, or excluded row so a dependency, state or conflict cannot quietly disappear. Use Supported row limit to show the top 12, top 20, or every retained row.
  • All 45 shows every lottery number. A dash in both Support and Context, together with zero in the score/count columns, means that none of the ledger's currently registered sources mentions that number.

Signal Confluence Independence Audit

The default-collapsed Signal Confluence Independence Audit is an observe-only truthfulness check. It asks whether two scored independence groups currently support more of the same numbers than two fixed-size random sets drawn from 1-45 would normally share.

  • Active groups counts independently capped groups with at least one currently supported number. Aggregators, consumer output and user state are excluded because they are context, not fresh evidence.
  • Observed / expected compares the actual shared-number count with the random-set reference |A| x |B| / 45.
  • Lift is observed overlap divided by expected overlap. Values above 1 mean more overlap than the reference, but lift alone does not trigger a warning.
  • Jaccard reports the shared fraction of the two groups' combined unique-number sets.
  • FDR q is the exact one-sided hypergeometric overlap result after Benjamini-Hochberg correction across every tested group pair. A pair is labelled Redundancy watch only when overlap is above expectation and q is at or below 0.05.
Important: this is a current-set overlap audit, not a certificate of statistical independence. A pair that is not flagged may still share inputs, history windows, or related logic. The audit never changes Bounded score, consensus rank, forced selections, or candidate generation.
Truthfulness boundary: confluence is agreement, not calibration. A number with many chips is worth inspecting, but it is not a probability and it is not a promise that the next draw will include it. Signal Confluence forced inclusions are user choices, remain separate in presets and Prediction Journal provenance, and count toward the same eight-number forced limit as other hard inclusions.

Unplayed Experimental Challenger: EP-R1

New portfolios freeze an additional EP-R1 four-row challenger alongside EP-1 and the uniform controls. It uses the same prior evidence, proposal pool, seed and number constraints. It is an unplayed shadow comparison, not a replacement recommendation. EP-1 construction and previously saved rows remain unchanged.

  • Frequency ties: equal appearance counts receive the same midrank support. Every number tied at the top-12 boundary remains included, so the list can contain more than 12 numbers. Numeric order is not evidence that one tied number is better.
  • Broad-support discount: frequency, drought and neighbour scores are multiplied by the unsupported share of the 45-number field. A family supporting 25 numbers uses 1 − 25/45 = 0.444. Supporting all 45 provides no discriminatory support. This is a fixed experimental heuristic, not a measured winning probability.
  • Stage fallback: when monthly-stage evidence is unavailable, the challenger's Stage Context row uses a disclosed coverage fallback instead of selecting another consensus row. The evidence gate is not weakened to manufacture stage support.

Open Unplayed experimental challenger to see the exact rows and methods. Saving a new portfolio retains them in the same journal entry for later real-result comparison and backup. Legacy entries without a saved challenger explicitly say so; the app never reconstructs one after seeing their outcome. Neither this challenger nor the replay automatically changes generator weights or supplementary assignment.

NS Diagnostic — CSV / Filter Reference

NS (NumSum Score) is still computed for export and filtering, but it is not currently shown as a visible Generated Candidates table column. It gives a percentile rank (0–100) of the candidate's total number sum compared against all historical draws. A score of 50 represents the median historical sum.

Honesty note: NS is a descriptive number-sum percentile, not a calibrated win probability. Treat high or low NS as a shape/context clue only.

How NS is calculated

  1. For every historical draw, sum all 8 numbers (6 main + 2 supplementary).
  2. Sort those sums into an ordered list.
  3. For a candidate, compute its total sum and find what fraction of historical draws had a sum less than or equal to the candidate's sum.
  4. Multiply by 100 to produce a percentile: NS = (# historical sums ≤ candidate sum) / (# draws) × 100

NS is wholly independent of Conv, IDM, Rdy and Nrr — it adds a pure "number-value gravity" axis derived from the actual draw history.

Nrr Diagnostic — Number Rarity Rank

Nrr is still computed for export, filtering, and the Recommended diagnostic sort, but it is not currently shown as a visible Generated Candidates table column. It scores candidates by how rare their numbers are within the generated candidate pool.

Numbers that barely survive constraint filtering — "contrarian picks" — were overrepresented in one internal candidate-sample analysis. Treat any lift figure as sample-specific and uncalibrated unless confirmed by fresh walk-forward testing.

Algorithm

  1. Count how often each number 1–45 appears across all generated candidates.
  2. For each number: Rarity = MaxFreq − Freq(number)
  3. Nrr for a candidate = sum of Rarity scores for all 8 numbers, normalised to 0–100.

Higher Nrr = rarer numbers in the generated pool. Use it as a rarity-based tiebreaker, not a guaranteed predictive signal.

IDM% measures how closely the candidate's bucket composition matches the active IDM target. The IDM target is the bucket recipe the app compares candidates against. If a row has been applied in Bucket Mix Combinatorics Explorer, IDM uses that applied bucket mix. If no Bucket Mix row is applied, IDM falls back to the Ideal pick mix emitted by Monthly Draws Summary's Robust Baseline and Ideal Draw. IDM is a descriptive alignment score, not a probability or guarantee.

  • 100% = perfect match to the ideal composition
  • Blue text (≥ 87.5%) = excellent alignment
  • Green text (≥ 50%) = good alignment
  • Grey text (< 50%) = poor alignment

The IDM target banner above the table shows the active source and composition, such as Bucket Mix Combinatorics Apply · 0x=5, 1x=2, 2x=1 or Robust Baseline / Ideal Draw · 0x=5, 1x=2, 2x=1. Stage IDM Column — Stage-Conditioned Ideal Draw Match

Stage IDM measures how closely a candidate's bucket composition matches the next draw-stage ideal composition emitted by Monthly Draws Summary. It uses comparable historical months with the same expected number of draws, then looks only at the stage we are planning for.

Example: if the working month is a 13-draw month, five draws have already happened, and the next draw is draw 6, Stage IDM learns from historical 13-draw months after their sixth draw. The score then asks: "does this candidate have the bucket mix that would best align with that stage-conditioned target?"

  • 100% = perfect match to the Stage IDM target composition
  • Blue text (≥ 87.5%) = excellent stage alignment
  • Green text (≥ 50%) = good stage alignment
  • Grey text (< 50%) = weak stage alignment
Honesty note: Stage IDM is not a calibrated next-draw probability. It is a descriptive alignment diagnostic that compares candidates against observed stage-conditioned bucket behaviour.

Rdy% Diagnostic — Readiness Score

Rdy% is a user-configurable composite of IDM, |Conv|, and OGA%. It is currently available through export/filter diagnostics and Readiness hard filters rather than as a visible main table column:

Rdy = (IDM_weight × IDM) + (Conv_weight × |Conv|_normalised) + (OGA_weight × OGA%_normalised)

Default state: all Rdy components are Off / 0%. Turn on and raise IDM, Conv, or OGA in Candidate Generation Setup → Engine & Ranking → Readiness (Rdy) Scoring. If OGA is off in the generation setup, the OGA component contributes 0 and the remaining active weights are normalised. The sliders are relative weights: if IDM is the only Rdy signal turned on, any positive IDM slider value displays as 100% effective weight because it is the only active component.

  • Gold text (≥ 70%) = excellent readiness
  • Green text (≥ 40%) = good readiness
  • Grey text (< 40%) = low readiness

Candidate Generation

Windfall Predictor (WP-1)

Windfall is for entertainment only and must never be treated as anything else. The Predictor name identifies an experimental candidate tool, not a calibrated or reliable lottery forecast. It sits first in Generation and starts closed. Its four 6-main + 2-supplementary suggestions are saved hypotheses, not purchased games or promised prizes.

  1. Load real history through the immediately preceding scheduled draw. Missing draws block construction rather than inventing evidence. Review shared forced inclusions and exclusions.
  2. Press Create four games. The seed makes sampling reproducible; it is not a lucky number. The four recipes are Balanced evidence, Monthly state, Neighbour / terminal, and Coverage hedge.
  3. Review the mains, suggested supplementary roles, neutral-evidence notices and the expandable evidence receipt. Mark Reviewed by user only after checking the output, then press Save to journal. One entry is labelled Created by Predictor · WP-1 · 4 games and retains all four games plus four unplayed controls.
  4. After adding the real target draw, revisit the Predictor's saved games or the journal entry. Every row receives an overlap flag, main-hit count, supplementary-role count and six-main prize check. No saved numbers are regenerated to improve their result.

Scope: live features use only the target month's recorded draws, not a rolling latest-13 window that can cross a month boundary. Earlier complete calendar months supply training. Incomplete prior months, including the partial opening month, are excluded; simulated, malformed, conflicting-date and off-schedule rows are not evidence. The current incomplete month is live context, never completed training. Global WFMQYH is neither changed nor used as a substitute. All eligible numbers 1–45 remain available, including numbers not yet drawn in the month.

What is learned: WP-1 groups monthly bucket and month-local gap into one family; unique directional neighbour masks into a second; and terminal-family heat, size and stage into a third. Early/middle/late means D1–D4 / D5–D9 / D10 onward. Terminal heat compares a family's observed count with its size-adjusted random expectation; fixed quiet/busy boundaries are 0.8 and 1.2 times that expectation. These definitions are experimental, not discovered laws. The model pools real historical number-state trials and shrinks sparse estimates towards the neutral 8/45 reference with 45 prior trials. Fewer than 20 observed state trials gives neutral weighting.

Gate and prior-only audit: three complete months are warm-up. Each later test month is held out in full; only after scoring it are its outcomes added to training for subsequent months. Each family needs at least 60 held-out targets across six months and a positive lower bound in an approximate 99% month-level Brier-improvement interval over the exact 8/45 reference. Brier error measures estimate error across all 45 numbers; lower is better. The interval is approximate and not a multiple-testing-adjusted proof. Passing this screen does not establish candidate-level prize advantage or calibrated winning odds. Failed gates stay neutral. If none pass, the panel says so; it does not substitute fabricated successes.

Construction: a passing family's relative sampling factor is capped at 0.8–1.2. Balanced evidence uses equal log-factor averages; Monthly state uses that family alone; Neighbour / terminal uses those two families equally. The hedge additionally favours numbers used less in the first three games, a diversity objective rather than extra evidence. Draws within a row are without replacement. Four distinct eight-number sets and distinct six-main rows are required; incompatible inclusions/exclusions stop construction.

Supplementary-role screen: a separate historical test reveals each held-out eight-number set but conceals its two supplementary roles. The candidate policy uses that month's prior supplementary counts and the DGA pair/prior-history tie-break policy, using completed earlier months only for its older reference. It needs 60 real targets across six months, a positive lower month-level interval for mean hits minus the exact random 0.5 reference, and exact-pair performance at least the random 1/28. Only a passing role policy is used in new suggestions. Otherwise all eight suggestions are uniformly shuffled to assign roles, including forced numbers, so construction order does not quietly bias which numbers become mains. This conditional role test does not establish that the app can discover the eight numbers beforehand. Actual subsequent results are also scored separately.

Applied settings: global forced inclusions and exclusions apply across each row's eight suggestions and its controls. Other main-generator filters, quotas, boosts and settings do not apply to this standalone fixed experiment. Existing observe-only drought, Auto supp challengers, confluence and other learners are not silently promoted into generator rules. The receipt records all applied constraints, source dates, training months, exclusions, seed, model version, audit results and per-number factors. Simulation copies the six mains and two suggested roles into DGA only; it never writes official history.

Reading outcomes: Hit means all eight suggested numbers overlap the actual draw, Partial means 1–7, and Miss means zero. Partial is not a prize and several overlaps are expected randomly. Six-main prize checks only the six listed mains against the real six mains and two supplementaries. Suggested supps cannot turn a standard six-number line into a prize. Supp-role hits separately tests the two proposed roles. The four uniform controls are generated unplayed comparisons, frozen before the result with the same number constraints; their outcome evidence comes only from the subsequent real draw.

Progressive self-review: records update their outcome flags when real history changes, without changing the frozen receipt. Formal comparison uses the earliest reviewed, unarchived WP-1 entry per target, created, frozen and reviewed before the target Melbourne calendar date. Same-day saves still get descriptive results because physical draw time is unavailable. Revised source history excludes a receipt from formal comparison. At least 30 distinct targets across six months are needed before a prospective comparison verdict; the primary measure is average actual-main matches in six-number rows, not portfolio spread coverage. Voluntary saves remain selection-biased. No automatic recipe changes occur. Newly completed real months update training when you next create games. JSON journal backup/import retains the Predictor flag, receipt and controls. Before the target arrives, the expanded journal entry offers Mark reviewed / Mark not reviewed; its frozen games and evidence cannot be edited into a different prediction.

This is the OGA information formerly shown in Next Draw Empirical Diagnostics, now explicitly retrospective. A saved favorite for the retired panel is redirected to Candidate Generation Setup.

The view reads the engine's existing OGA distribution rather than calculating a second independently configured version. Evidence is the active real WFMQYH sample. Reference comes from Forecast baseline: Windowed uses that sample; Full History uses all loaded real history, including the partial opening month. Choosing Full History does not expand the evidence sample. Number groups mirrors OGA number groups (formerly Windowed Spokes). It has no local switches and does not change generation.

What the current OGA formula actually measures: it partitions 1-45 into consecutive number groups, divides each draw's group count by that group's historical average plus 0.001, then adds the ratios. This is a group-frequency diagnostic, not a measurement of angles, distances, symmetry or proximity to a historical shape. Different number sets with identical group counts receive the same score. When the evidence sample is its own reference, the mean tends toward the number of occupied reference groups by construction; a mean near 8.99 with nine populated groups is not evidence of forecasting skill. The no-history absolute-deviation fallback is a different calculation and is not displayed as historical evidence here.

Any future replacement of its shared formula needs separate no-lookahead validation and explicit versioning; this consolidation leaves the existing generator mathematics, presets and saved journal entries unchanged.

Preferred OGA Score Bands

Find this in Candidate Generation Setup → Engine & Ranking → OGA Reference And Ranking → OGA Forecast Bias (KDE). Preferred OGA score bands (advanced) is collapsed by default. These controls affect candidate acceptance, not Draw Composition Quotas or the requested percentage split.

  • Enable OGA acceptance bias defaults off. Turning it off preserves your settings without applying them.
  • Forecast baseline: the band cutoffs describe scores of the active WFMQYH draws. Both those historical scores and each candidate's score use the same reference: Windowed or Full History. Full History changes that reference, not the active WFMQYH evidence sample. The panel and Trace report both scopes.
  • No detailed selections: Low/Mid/High or Auto controls acceptance as before.
  • Detailed selections present: only selected D0–D9 intervals with positive weights may pass. Low/Mid/High is inactive, and a failed decile check never falls back to it. Clear bands to return to the broad-band rule.
  • D0–D9 are ten OGA score intervals, not monthly draw ordinals or terminal digits. D0 includes scores at or below the first cutoff; intermediate intervals are above their lower cutoff and at or below their upper cutoff; D9 is above the last cutoff. Cutoff ties go to the lower interval. Tied cutoffs can leave an interval empty, so these are not guaranteed equal-count groups.
  • Weights: algorithm acceptance inside a selected band equals its weight divided by the sum of selected weights. Example: D4 weight 2 and D7 weight 1 gives acceptance rates of 2/3 and 1/3 for candidates already in those respective bands. This does not promise a 2:1 split in final candidates: the initial score distribution, hard filters and final survivor selection also matter.
  • Weight 0: that band cannot pass. An all-zero selection, unavailable/invalid cutoffs, or selections confined to empty intervals block standard generation with an explanation; no substitute band is silently used.

Preferences apply to subsequent generation runs; changing them does not re-filter previously generated rows. Trace records the selected-only policy, reference history, full-precision cutoffs, unselected/zero-weight rejects, weighted rejects and gate passes. A gate pass is not necessarily a final accepted row. RwR45/PNUaRW45 bypasses this OGA gate and reports that explicitly. Effective Settings model WF-settings-4 identifies the repaired behavior in new snapshots; older journal entries are not rewritten.

Truthfulness: acceptance rates describe the generator's random acceptance step, not the likelihood of winning or of an OGA band occurring in the next draw. These are diagnostic preferences, not calibrated predictions.

Drought Evidence Governor

Find this under Candidate Generation Setup → Composition & Recency → Recency & Latest Draw Rules → Drought quota counts. The governor changes the sampling weight of eligible drought shortlist numbers during candidate construction. It defaults off.

  • Mode: choose exactly one radio option: Off, Auto evidence, or Manual weights. Off is the default and gives every number a neutral 1.00x from this governor. Changing mode preserves your bucket choices and saved manual weights.
  • Auto evidence: Windfall checks the historical replay gate for strict drought and empirical hazard separately. It calculates modest weights only for families that pass.
  • Manual weights: you choose the weights, even if the Auto gate fails. This is a user-set experiment, not a calibrated prediction.
  • Planning context: 2026-09 13D D7 means September 2026, an expected 13-draw month, with D7 as the next target draw. The panel and each generation Trace show the same context.
What “Strict active” means

The strict drought 6+ shortlist ranks numbers absent for at least six consecutive real draws. The empirical hazard shortlist ranks smoothed historical next-hit rates at the current drought length, so it can contain numbers with shorter droughts. Current shortlists use the app's active history inputs; strict drought age also uses full real history. Auto advice is replayed using baseline history, with each historical shortlist built only from draws before its target.

Strict replay first looks for the same expected month length and draw ordinal with at least 6 trials. If unavailable, it tries the same ordinal across months with at least 12 trials, then all eligible baseline trials with at least 24. Strict advice needs a 1–3-hit rate at least 2 percentage points above the random baseline, or an average hit count at least 0.12 above random. Empirical advice uses all eligible baseline transitions and needs an observed chance of at least one shortlist hit of at least 15%, at least 2 percentage points above random.

The governor additionally requires positive replay advice, at least one trial, and either a 1–3-hit lift of at least 2 percentage points or an average-hit lift of at least 0.10. Auto gate: passed reports those checks. The panel shows the source, number of trials, observed 1–3-hit rate and average hits beside their random baselines. An active family must also have allowed numbers receiving a weight above 1.00x.

Evidence limits: These are heuristic thresholds, not a statistical significance test or calibrated win probability. Replay measures the original shortlist. A user-selected bucket subset or manual weight has not been separately validated by that replay.
Strict buckets and empirical buckets

Each family has its own bucket checkboxes. The number in parentheses is a measured count of eligible shortlist numbers in that bucket, after active exclusions. 0x (8) means eight shortlisted numbers are undrawn in the planning month. 0x (4), 1x (3), 2x (1) means four are undrawn, three have appeared once this month, and one has appeared twice. These counts are facts and cannot be edited.

Checking a bucket allows its shortlist numbers to receive this governor's weight; unchecking it removes that family's contribution. You can select any combination, all, or none independently for strict and empirical. A shared number may still receive the other family's weight. These checkboxes do not require a candidate to contain a particular count. The separate strict and empirical quota controls enforce minimum counts.

Carry-over overlap numbers

This label lists numbers that occur in either eligible shortlist and were undrawn at the previous month-end. Carry-over overlap numbers: 3 · Count 1 identifies number 3 and one overlapping number.

Weight carry-over numbers defaults on within the governor to preserve the previous eligibility behavior. On allows their ordinary governor weights and adds no separate carry-over bonus. Off makes their governor weight 1.00x in both families, including manual number overrides. It does not exclude those numbers from generation; other controls may still weight or require them.

Editable soft weights

Manual mode offers a Strict soft weight and an Empirical soft weight, each from 1.00x to 1.45x in steps of 0.01. Manual defaults start at 1.00x (neutral). For numbers in both allowed families, weights multiply, capped at 1.45x. For example, strict 1.20x and empirical 1.10x combine to 1.32x.

The scrollable Governor multiplier ledger shows every eligible number, its shortlist membership, rank and drought age, current bucket, carry-over status, applied weight and weight source. r2 / 11 draws means rank 2 with a drought of 11 draws. In Manual, the per-number selector can replace the combined family weight with an exact value. Choosing Family weights removes that override. Reset number overrides removes all saved per-number overrides.

Example: number 3 with Applied 1.17x has its construction weight multiplied by 1.17. It does not have a 17% chance of being drawn. Decimal multipliers are retained by the weighted sampler, including random monthly constructive fill. Other influences multiply alongside them. Hard inclusions, exclusions and filters still apply; coverage-planned slots are filled directly and RwR45 bypasses evidence weighting.

After new real history arrives, the context, bucket counts and shortlists refresh. Manual settings persist in state presets, and per-number overrides remain attached to their number until reset. An override applies only while that number is in an allowed current shortlist. Auto ignores saved manual weights.

Trace and predictions: Each run records the mode, planning context, measured bucket counts, allowed buckets, carry-over numbers and count, gate results, manual settings and actual multipliers. The governor ledger's accepted-pool count counts occurrences before final survivor selection; it can be much larger than the count in the displayed candidates. New prediction snapshots capture the governor settings and applied weights so later review can distinguish Auto from Manual experiments.

Monthly Bucket Transition Governor

The Monthly Bucket Transition Governor sits in Candidate Generation Setup → Shape / Bucket Quotas, directly below Single-digit / two-digit share and above Monthly bucket construction. It is a default-off soft generation influence that studies how numbers have historically moved through month buckets at the same stage of the month.

When set to Auto evidence, Windfall checks the next draw ordinal, the expected number of draws in the planning month, the current monthly bucket state, and completed baseline months. It then decides internally whether the current stage has enough support for a cautious boost. The first implemented transitions are:

  • Early 2x-to-3x formation: at target draws D3–D5, checks current 2x numbers.
  • Delayed first 4x transition: at target draws D7–D9, checks current 3x numbers, only when no 4x-or-higher number exists yet.

Transition influence choices:

  • Off: no weighting from this governor.
  • Auto evidence: Windfall chooses whether to boost and its strength from the historical gate below.
  • Manual light (1.10x), normal (1.25x), strong (1.40x): your chosen fixed multiplier applies to numbers in an eligible source bucket, even if Auto's evidence gate fails or has too few trials. These are user-set experiments, not evidence-backed recommendations.

Manual strengths do not change the draw-stage rules above. No boost applies outside those stages, when the source bucket is empty, when the delayed-first-4x transition has already occurred, or when planning context is unavailable. For example, at D8 with numbers 12 and 18 in 3x and no 4x-or-higher number, Manual normal gives both 12 and 18 a 1.25x sampling weight. This does not mean a 25% draw chance or a guarantee they will be included. Other weights combine with this weight and hard filters still decide acceptance.

Live shared setting: when enabled, the same governor setting appears in Monthly Draws Summary, Monthly Bucket Transition Lab, Generated Candidates, and Paste-Weighted's monthly controls. The readout separates Selected mode from the effective Main generator weight. Expand Monthly transition details for the current numbers, exact multipliers, baseline scope and reasons. Edit opens the one owning control, even when its setup card is collapsed. Changing the mode updates these readouts immediately; Off hides them. RwR45/PNUaRW45 shows a bypass instead of claiming a boost. Monthly summary and lab calculations are unchanged, and Paste-Weighted does not apply this main-generator governor. Bucket counts, Acceptance Needs, Stage IDM targets and independent local lab settings are not overwritten.

What earns an Auto boost: there must be at least three eligible earlier months. For those months, the share with at least one next-draw transition must beat the random baseline by at least 4 percentage points or 12% relatively, and the hit rate per available source-bucket number must also beat its random baseline (8/45 with mains + supps). Random expectation accounts for how many numbers were available in that bucket. These are experimental thresholds, not proof of predictive accuracy. Manual modes display the same evidence without requiring it to pass.

First arrival is different from next-draw evidence: knowing that most months had reached 4x by D8 does not show that a number is more likely to move from 3x to 4x on the next draw. Cumulative first-reach timing is displayed for context only; it cannot activate or strengthen a boost. For the delayed-first-4x rule, only historical months with no 4x-or-higher number before the target draw are compared. Future months, incomplete months and months with date/schedule gaps are excluded from the governor's baseline.

How to read the Auto message: if the panel says Auto checked current stage-transition evidence, but no configured transition cleared the evidence gate for this draw context, Windfall checked the current month stage and decided not to boost anything. That can mean the next draw is outside the configured stages, the relevant bucket has no numbers, the evidence was too weak, or the transition has already happened. A line such as Scope: 18 completed 13D baseline months means Windfall compared the current setup with 18 completed historical months that also had 13 draws.
Truthfulness note: this governor does not force a number, does not override exclusions, does not replace Acceptance Needs, and does not claim a calibrated probability. It only changes sampling weight before hard filters run. The panel and Trace report requested mode, applied strength, planning context, baseline scope, evidence gate, and exact multipliers. Trace counts refer to the accepted pool before final survivor selection. State presets restore the mode; new Prediction Journal setup snapshots preserve the mode, applied weights and Trace explanation. Existing journal entries remain unchanged. RwR45/PNUaRW45 bypasses this governor.
Transition Watch above Generate

Transition Watch is a compact pre-generation advisory shown at the top of Generated Candidates only when the current draw stage passes the governor's Auto evidence gate. It names the source and target buckets, lists the currently eligible numbers, and compares the observed at-least-one transition rate with its random baseline. Thin sample means fewer than 12 eligible comparable historical months were available, so the result deserves extra caution.

The watch calculates its evidence even when Transition influence is Off. Its Generation influence line is therefore important:

  • Off · advisory only: the evidence is visible, but it does not alter candidate generation.
  • Auto or Manual with a multiplier: the displayed eligible numbers receive that soft construction weight before hard filters.
  • Bypassed by RwR45 random coverage: the evidence remains visible, but RwR45 does not apply the governor's weight.

Open Evidence details for the planning context, baseline scope, at-least-one and per-number comparisons. Review evidence opens the full Monthly Bucket Transition Governor controls. The watch never means that a transition is due, expected, guaranteed or a forced inclusion. It disappears when no stage-conditioned rule clears the evidence gate or when the relevant transition has already occurred.

Latest Neighbour Support (LD±1 / LD±1/±2)

This control lives inside Candidate Generation Influences → Composition & Recency → Latest Draw ±1/±2 Constraint Builder. The manual builder forces exact selected -2, -1, +1, or +2 target numbers. Latest neighbour support is the automatic companion rule: it computes its own eligible target set from the latest real WFMQYH draw and requires every generated candidate to contain at least one eligible target when switched on.

When latest neighbour support is ON, Windfall:

  • takes the latest draw's main and supplementary numbers and creates valid targets inside 1–45;
  • uses the selected mode: ±1 only creates source - 1 and source + 1; ±1 and ±2 also creates source - 2 and source + 2;
  • removes targets already selected as hard exclusions;
  • disqualifies targets that have appeared in more than seven consecutive draws inside the recent 10-draw streak check;
  • uses current monthly bucket state, when available, to disqualify drought-heavy targets whose terminal digit still has two or more companion numbers in the undrawn bucket, except when the next draw is treated as the last draw of that month;
  • coordinates 0-ending and 5-ending targets with the existing ending-digit controls rather than silently overriding those controls.

Eligible targets receive a modest construction boost and then become a hard minimum-one filter. If no eligible targets remain, Windfall skips the hard filter and records the reason in Trace rather than rejecting every candidate. The pre-flight Trace also reports whether the latest-neighbour target cloud is compatible with active Stage-Match or Acceptance Needs bucket counts.

Month-boundary note: latest neighbour support uses the same shared next-draw planning context as Monthly Draws Summary. A completed source month, such as July after its final draw, is not treated as "planning the last draw" when the actual next target is the first draw of August.
Truthfulness note: LD±1 and LD±1/±2 are experimental support rules, not calibrated probabilities or proof that a nearby number will draw next. Use the Trace output to inspect which numbers were eligible, which were disqualified, and how many candidates were rejected by the rule.

Drought Quota Counts

This control lives in Candidate Generation Influences → Composition & Recency. It uses the current Drought-break shortlist (mains + supps) as candidate-construction evidence. The rule family is default Off.

  • Strict drought 6+ uses numbers whose current full-history drought is at least six draws, ranked by strict drought severity and episode evidence.
  • Empirical hazard uses numbers ranked by the smoothed empirical next-draw appearance rate for their current drought length.
  • Off leaves generation unchanged and only displays the current eligible shortlist.
  • Manual minimum requires every generated 8-number candidate to contain at least the selected count from that shortlist family.
  • SDSR-advised asks the Strict Drought Shortlist Replay for the current planning draw context. If the exact month-length/draw-ordinal slice is thin, it falls back to same draw ordinal, then to all eligible rows. The advised minimum is capped at 1.
  • Hazard-advised uses no-lookahead empirical hazard replay rows across the validation baseline. It applies a quota only when the count evidence beats an equal-size random baseline enough to justify it. The advised minimum is capped at 1.

The generator seeds from the eligible shortlist before the normal weighted fill, then verifies the final candidate before accepting it. Strict and empirical quotas are checked separately. If a number appears in both shortlists, it can satisfy both evidence categories while still occupying only one candidate slot. Active exclusions still win: if SDE1, HC3, user exclusions, or MiAN remove shortlist numbers, Trace reports the smaller effective minimum instead of silently forcing an impossible rule.

The count replay chips read as minimum-count tests. For example, ≥2 obs 41.0% rand 38.5% +2.5pp means that in the no-lookahead replay, at least two numbers from that shortlist appeared in 41.0% of tested draws, while an equal-size random shortlist would be expected to do that about 38.5% of the time.

Truthfulness note: these are quotas based on replay evidence, not probabilities or promises that a drought number will appear. Use Trace to confirm the active minimums, eligible shortlists, replay slices, and rejection counts.

When you select a target number, it joins the generator's forced-number list together with any Number Trends forced numbers. The table columns Prev±2, Dup±2, and Dir±2 remain observe-only diagnostics that show how generated rows relate to the latest draw's -2, -1, +1, and +2 neighbour targets.

The builder also houses Latest neighbour support (LD±1 / LD±1/±2). This automatic rule is default off; the manual target buttons are user-directed forced inclusions. Keeping them together makes it easier to compare automatic latest-draw support with exact manually selected neighbour targets.

  • White target buttons are valid generated targets that are not currently selected.
  • Amber target buttons mark duplicated targets: the same target number can be reached from more than one latest-draw source number.

Single-digit / two-digit share

This control lives inside Generation Constraints. It lets you enforce the percentage split between:

  • Single-digit numbers — numbers 1–9
  • Two-digit numbers — numbers 10–45

The two dropdowns are linked. If you choose a value in one selector, the other selector automatically updates to the remaining percentage so the total always stays at 100%.

Scope

The Count against selector changes how many positions are included in the rule:

  • Mains only — the rule is applied over 6 numbers
  • Main + supps — the rule is applied over 8 numbers

How the exact counts are derived

The generator converts the selected percentage into exact counts per candidate:

  • Single-digit count = floor(percentage × counted slots)
  • Two-digit count = remaining counted slots

Example: if Single-digit % = 25%, then Two-digit % = 75% automatically.

  • Mains only (6 numbers) → 1 single-digit + 5 two-digit
  • Main + supps (8 numbers) → 2 single-digit + 6 two-digit
The app shows this exact target directly under the selectors so you can see the real candidate composition implied by the chosen percentage and scope.

Strict enforcement

This is a hard generation rule. Candidates that do not match the exact single-digit / two-digit target are rejected during generation.

Because candidates are made of discrete slots, some percentage choices map to the same exact count. The displayed target is the real rule that will be enforced.

Trace panel

When this rule is enabled, the Trace panel records:

  • the selected percentages
  • the selected scope
  • the derived exact target counts
  • the number of candidate rejections caused by this rule

Count and Attempts ×

  • Count — number of candidates to keep in the final table.
  • Attempts × — multiplier applied to Count to set the total generation attempts budget (e.g., Count 100 × Attempts 400 = 40,000 attempts).

Ending-digit limits and boosts

Each row in Generation Constraints has one hard count rule and two separate boost inputs:

  • Mode — chooses whether the terminal digit rule is Off, At least, Exactly, or At most.
  • Count — the number used by the selected Mode. Exactly 2 means every accepted 8-number candidate must contain exactly two numbers from that terminal digit bucket.
  • 1-digit boost — boosts only the single-digit member of that ending-digit bucket, such as 1 in bucket (1, 11, 21, 31, 41).
  • 2-digit boost — boosts only the two-digit members of that bucket, such as 11, 21, 31, 41.

Boost values still apply even if the terminal digit count rule is Off. They change the sampling weight used during candidate generation for both main and supplementary picks; they do not force, require, or cap that many numbers.

Example: if terminal digit 2 is set to Exactly 2, every accepted candidate must contain exactly two numbers from 2, 12, 22, 32, 42. If 2-digit boost is also raised, the generator gives 12, 22, 32, 42 extra sampling weight while still enforcing exactly two total 2-ending numbers.

When any split boost is active, the Trace panel records both:

  • the configured split boosts, such as bucket 1 single-digit +5, bucket 1 two-digit +2
  • the accepted-candidate results, showing how many boosted candidate hits actually appeared in the generated output

Repeated Terminal Digit Families

Repeated Terminal Digit Families counts terminal digits that occur at least twice inside a candidate. It is a hard candidate rule when enabled, not a probability and not a prediction.

  • Mode chooses Off, At least, Exactly, or At most.
  • Families is the number of repeated terminal digit families required by the selected Mode.
  • Count against chooses whether the rule reads the six main numbers only or all eight main + supplementary numbers.
Example: 33, 27, 21, 31, 26, 43 has two repeated terminal digit families in mains only: 1 and 3. Adding supps 30, 20 creates a third repeated family, 0, when the scope is mains + supps.

A repeated family is not the same as a terminal digit pair list. Two or more numbers ending in the same digit create one repeated family for that digit. Trace reports how many candidates were rejected by this rule under repFamilies.

Over-generation Pool

The Overgen × field sets how many times Count is generated as an initial pool before filtering down to Count. Higher values give the scorer more candidates to choose from and improve result quality, at the cost of memory and time.

Overgen > 200× may use significant memory. A red warning appears if this threshold is exceeded.

MiAN — Must Include from Acceptance Needs

The Must Include from Acceptance Needs (MiAN) toggle requires every accepted candidate to contain at least a specified count of numbers from each monthly frequency bucket.

Synced mode

When "Use these counts when constructing candidates" is ON in Monthly Draws Summary, the MiAN values are automatically synced from the "Acceptance needs" row — they become read-only (shown with a green tint and 🔗 sync notice). This ensures MiAN always reflects the actual selections made in Monthly Draws Summary.

In this synced mode, the same bucket counts are used in two places:

  • Constructive fill — used while building candidates.
  • MiAN post-filter — checked again after candidates are generated.

This means constructive fill tries to steer candidates toward the required monthly bucket mix, and MiAN then acts as a final guard to reject any candidate that still misses those minimum bucket counts.

When constructive fill is OFF, the 9 bucket count inputs are fully editable.

Hard exclude zero-count buckets

When this sub-toggle is enabled, all numbers in buckets whose required count is 0 are excluded from the candidate number pool entirely before constructive fill and before the normal weighted generation step. This is a stronger constraint than the acceptance filter alone.

Example: if the required counts are 2x = 0, 3x = 0, and 6x = 0, then every currently eligible number in those monthly buckets is removed from the generator pool before any candidate numbers are chosen.

Monthly Repeat Bias

Boosts the selection probability of numbers drawn exactly once this month (the 1x bucket). Use this as a configurable historical bias toward possible monthly repeats, not as a guarantee that 1x numbers will repeat before month-end.

  • Boost factor — how many times more likely a 1x number is to be selected (1 = no boost, up to 10).
  • Include supplementary numbers — if checked, the boost also applies when filling supplementary positions.

Effective Settings and Saved Intent

Saved Zone weights: saving weights from Group Pattern Analyzer immediately refreshes open Survival, Temperature Transition and shared analysis consumers, including another tab at the same browser address. A page refresh is not required. The global weighting switch and strength still determine whether those saved weights are applied; refreshing the evidence does not turn a weighting control on.

Shared versus local controls: active hard-number exclusions are passed to Paste-Weighted, Bates and Parameter Search rather than just displayed as warnings. Other constraints remain generator-specific unless their panels explicitly say otherwise. Saved prediction snapshots stay frozen; updating live settings does not rewrite a historical entry.

Open Active Setup Summary → Effective Settings to compare requested settings with what is applied. Each row records its source, effect, history scope and reason. Restored means the request matches a restored ledger; Control means the current control value (including legacy presets without a ledger); Automatic means you delegated a choice; Fixed model means a disclosed internal assumption rather than a user adjustment.

The Recency & Latest Draw provenance group also reports the shared Neighbour Atlas source, scope, lookback, target draw stage, cloud size and ordinal sample label. It is marked observe-only so seeing it in the setup summary cannot be mistaken for an active generator setting.

Autosave reads the current setup every two seconds, after startup restoration. A storage error is reported instead of claiming the setup was saved. Custom WFMQYH and manually edited repeat windows survive history changes. Hard manual drought or newest-pool minimums remain unchanged if their eligible pool shrinks; impossible requests block generation rather than being silently weakened.

Neighbour and drought quotas now have separate, default-off construction-weight switches. Quota-only means neutral extra weight. The neighbour switch adds 3x; drought rank weighting uses 1 + (list size − rank + 1) / list size: 2x first to 1.125x eighth on an eight-number list. Strict and empirical factors multiply when both apply. They are configurable experiments, not measured increases in winning chance.

Standard-generation Trace records this ledger and all 45 per-number sampling factors before row-specific pool normalization and hard filters. Monthly clicked-number constructive bias, when enabled, adds its separately reported 3x only within the relevant bucket. Other pools or constraints can change final selection rates, so the trace weight is not the eventual inclusion probability.

New Prediction Journal snapshots keep the same versioned Effective Settings ledger. Older entries remain unchanged. Standard worker generation records a seed; replay also requires the identical history, inputs and model version. This seed is not a complete replay guarantee for batch or RwR45 modes, which follow separate paths. RwR45 bypasses evidence rules, and Trace identifies that bypass explicitly.

Month-end carry-over bias

This toggle reuses the Month-end carry-over study as an actual weighting signal rather than just a display panel.

  • When ON — numbers in the active carry-over pool can receive extra or reduced weighting during candidate generation, and candidate ranking can include a carry-over component.
  • Influence — choose Light, Normal, or Strong to control how far carry-over weights move away from neutral and how much ranking influence they receive.
  • Signal sources — use separate checkboxes for still-undrawn month-end numbers and last-to-first boundary repeats. This lets you keep the more direct undrawn signal while turning off boundary-repeat evidence if it feels too speculative.
  • Clicked boost — when carry-over numbers are clicked from the month-end bucket panel, choose Normal, Strong, or Near-forced instead of always using one fixed massive boost.
  • Explicit opt-in — carry-over starts OFF. Turn it on manually, or enable Auto-enable for positive early-month evidence. Auto applies it only within the first 3 planning draws when at least one eligible weight exceeds 1. Selecting carry-over numbers no longer turns the influence on. Turning the main toggle off also leaves Auto mode.
  • Planning month logic — Windfall uses a shared next-draw planning context rather than the largest month length in history. If a 12- or 13-draw month is complete, it can still roll forward correctly even when other months contain 14 draws.
The panel now labels active weights as boosts or penalties. For example, 13×0.93 penalty means number 13 is in the active carry-over pool, but the learned evidence slightly reduces its generation/ranking influence rather than favouring it.

Last Draw Match Controls

These controls live together in Candidate Generation Influences → Composition & Recency. They all refer to the single most recent real draw in the active WFMQYH window, but they do not all behave the same way.

WFMQYH is not the same thing as latest-draw overlap. WFMQYH chooses the draw-history evidence universe the app can learn from. For example, setting WFMQYH to the latest 9 draws means many evidence panels and generation weights use those latest nine real draws as their active history. It does not by itself force generated candidates to contain numbers from those nine draws.

  • Last-draw overlap rule is the strict filter. Choose Off, At least, Exactly, or At most, then choose the count.
  • At least 2 means every accepted candidate must contain two or more numbers from the latest draw.
  • Exactly 2 means every accepted candidate must contain exactly two numbers from the latest draw.
  • At most 2 means every accepted candidate may contain zero, one, or two latest-draw numbers, but not three or more.
  • Exactly 0 is the clean no-repeat setting. Every accepted candidate must contain no numbers from the latest draw.
  • Last-draw match bias is not a strict filter. It is a soft weighting strength from 0 to 5. 0 is off; 5 is the strongest setting.
Common zero-setting example: Off means the hard latest-draw overlap filter is off. Candidates may contain 0, 1, 2, or more numbers from the immediate previous draw. This does not mean "reject every candidate that contains a latest-draw number."
Fast no-repeat workflow: choose Exactly and set the count to 0. This is the cleanest way to force no latest-draw repeats. The broader User Selected Numbers → Select All workflow can also be used to define a custom eligible number space, then Exclude unselected can hold out anything you manually deselect.

The bias changes direction depending on the strict rule. With a positive minimum (At least or Exactly above zero), latest-draw numbers receive a construction multiplier of 1 + bias. Without a positive minimum, they receive 1 / (1 + bias). At bias 5 these are 6x and about 0.167x, respectively. Both are positive sampling weights, not acceptance probabilities. The bias never rejects a candidate by itself, and cannot override Exactly 2 or another hard overlap rule.

Truthfulness note: Last-draw match bias does not mean "only choose numbers from the last draw." The strict include/exclude behaviour comes from the Last-draw overlap rule.

Look back over newest draws is separate from the single last-draw controls. It builds a wider pool from the newest W draws inside active WFMQYH history. Use current-month default follows the latest observed month's completed draw count. Editing W turns that automatic default off. Your requested W and Custom WFMQYH count are preserved when history or context changes; the effective window uses only available draws.

The control shows the count of unique numbers found in that newest-draw pool. The Minimum candidate numbers from that pool field accepts 0-8 and retains your request. If too few eligible numbers remain, generation is blocked with an explanation; the app does not silently lower a manual minimum. Monthly bucket requirements may further reduce the compatible maximum shown beside the field.

Example: if Stage-Match requires 0x>=2 and the newest-draw pool covers the current month's completed draws, then current-month 0x numbers are outside that newest-draw pool by definition. In that setup, at least two candidate numbers must come from outside the repeat pool, so the repeat-pool minimum cannot be higher than 6. Windfall reports this as a repeat + monthly bucket compatibility warning in Trace.

Example: with WFMQYH set to the latest 9 draws, Look back over newest draws set to 9, and Minimum candidate numbers from that pool set to 6, Windfall builds one union pool from every number seen in those nine active draws and accepts only candidates containing at least six numbers from that pool. That is different from Last-draw overlap rule, which checks only the immediate previous draw.

  • At least, not exactly: a minimum of 5 means accepted candidates must contain 5 or more numbers from the union pool.
  • Full candidate scope: the check counts all 8 candidate numbers: 6 mains plus 2 supplementary numbers.
  • Appeared once is enough: a number only needs to have appeared at least once in the newest W active draws to be part of the union pool.
  • Active-window cap: if WFMQYH currently contains fewer draws than the lookback value, Windfall uses only the available active WFMQYH draws.
  • Constraint conflicts still matter: if exclusions, forced numbers, odd/even quotas, bucket rules, or other filters make the requested minimum impossible, generation may struggle or return fewer candidates. Any accepted candidate should still satisfy the active minimum-from-pool rule.

Bucket Coverage Planner

Bucket Coverage Planner is a default-off helper in Candidate Generation Setup. It works only with active Acceptance Needs or Stage-Match bucket counts. Instead of choosing required bucket members purely at random, it tries to spread generation across the possible within-bucket combinations before later filters run.

The planner first calculates the combination burden for each planned bucket. For example, if the current 1x bucket has 8 eligible numbers and the candidate needs 2 of them, the burden is C(8,2)=28. That means 28 candidates are needed to cover every possible 2-number pairing from that bucket once.

Leave Undrawn random is on by default. This keeps any 0x / Undrawn count active, but removes the Undrawn bucket from the coverage maths. The reason is practical and honest: early in a month, the Undrawn bucket can be so large that trying to cover every possible Undrawn combination instantly becomes misleading or unusable. With this option on, Windfall still fills the required Undrawn count, but does so by standard random constructive fill while planning the smaller drawn-count buckets.

Stage IDM

Stage IDM is a second Ideal Draw Model that conditions the target on the current month stage. It first identifies the working month, estimates or uses the selected expected draw count for that month, then computes the next planning stage from the number of draws already loaded.

It then filters history to comparable prior months with the same expected draw count and enough draws to reach the planning stage. From those comparable partial-month states, it builds a robust bucket target and computes an ideal 8-number bucket mix by exhaustive SSD minimisation.

The Expected Draw Count selector can be left on Auto or set manually. Auto infers the expected count from the recent draw weekday rhythm; manual override is useful when you already know the month will contain a specific number of draws.

How to use it: compare the normal IDM target with the Stage IDM target. When they disagree, Stage IDM is usually answering the narrower question: "what does this stage of a like-sized month tend to need now?"
Thin evidence warning: if only a small number of comparable months exist, treat the Stage IDM target as exploratory. The panel will show a warning rather than pretending the evidence is stronger than it is.

How to read the lab

Read this panel as a movement diary, not as a prediction panel. It is designed to show how numbers have historically moved from one monthly bucket state to another.

  1. Start with Evidence Length. Auto usually means the lab is comparing against same-length months, such as 13-draw months. All lengths pools every baseline month. For monthly-bucket behaviour, Auto is usually the cleaner first read.
  2. Read Current-Stage Transition Expectation next. This is the most immediately useful table. Focus on Count now, Trials, Smoothed rate, and Expected next hits. For example, if Undrawn has 18 numbers now and Expected next hits is 3.1, the lab is saying that historically about three next-draw numbers might reasonably come from currently undrawn numbers at this stage.
  3. Use Markov Forward Bucket Projection for the month path. This takes the current bucket state and projects it forward one draw at a time. It is useful for seeing whether the month is expected to keep converting Undrawn numbers, build 2x/3x, or push into upper buckets by month-end.
  4. Use Undrawn Survival / Break Curve for carry-forward behaviour. Look for where the median undrawn count falls sharply. If it tends to drop between D6 and D9, that supports the observation that undrawn carry-over often breaks around the middle to later-middle part of the month.
  5. Use Upper-Bucket First Reach Timing for rarity checks. This table helps answer questions such as whether 4x by D6 is early, whether 6x+ mostly appears in longer months, and what bucket levels are normal by the current stage.
  6. Use Month-Length Final Shape Comparison for 13d versus 14d questions. This table uses completed months only and is the safest place to inspect whether longer months finish with fewer undrawn numbers or more upper-bucket numbers.
  7. Use Prior Heat x Monthly Bucket Relationship last. This checks whether hot/cold status adds information inside a monthly bucket. If Hot / Undrawn has a higher smoothed rate than Cold / Undrawn, heat may add useful context. If the rates are similar, heat is probably not adding much for that bucket movement.

Constructive Fill

The "Use these counts when constructing candidates" checkbox passes the Acceptance needs counts to the generator as hard requirements. When ON:

  • Every generated candidate must contain at least the specified count from each bucket.
  • The MiAN values in Candidate Generation Influences are automatically synced (see MiAN).

How numbers are chosen from a bucket

During constructive fill, the generator receives:

  • bucket counts — how many numbers are needed from each bucket, and
  • bucket sets — all currently eligible numbers in each bucket.

If a bucket contains more numbers than required, the generator normally picks from that bucket by uniform random sampling without replacement. When Bucket Coverage Planner is ON and the burden is acceptable, it replaces that random bucket-pick step with planned full or sampled coverage for planned buckets. If Leave Undrawn random is on, the Undrawn count remains required but uses the normal random bucket fill.

Examples:

  • 1x 5/17 means the generator needs 5 numbers from the 1x bucket, so it randomly samples 5 from the 17 currently eligible 1x numbers.
  • 4x 1/5 means the generator needs 1 number from the 4x bucket, so it randomly samples 1 from the 5 currently eligible 4x numbers.

The exact constructive-fill order is fixed:

  1. Undrawn
  2. 1x
  3. 2x
  4. 3x
  5. 4x
  6. 5x
  7. 6x
  8. 7x
  9. 8x+

As numbers are picked, the generator fills the candidate main numbers first until there are 6 mains, then fills the remaining supplementary positions until there are 2 supps.

When constructive fill happens relative to other generation rules

The order matters:

  1. Exclusions are built first — including user exclusions, SDE1, HC3, and any Hard exclude zero-count buckets removals.
  2. Constructive fill runs next — bucket counts are used to seed the candidate.
  3. An early digit-width guard runs — if the seeded candidate already breaks the single-digit / two-digit target, that attempt is rejected immediately.
  4. Any remaining open slots are then filled by the normal weighted generator.
  5. Full-candidate constraints are checked after the 8 numbers are assembled.

This means the constructive bucket picks happen before the later weighted-fill influences such as:

  • Digit decade boost / punish
  • n-ending terminal digit count rules (checked later as hard constraints)
  • Single digit / two digit share
  • Selected-number boost
  • Monthly Repeat Bias
Constructive-fill picks themselves are not weighted by decade boosts or ending-digit boosts. Those weighting systems only influence the later remaining-slot fill stage if the candidate still has empty positions after constructive fill.

What happens when the selected counts already total 8

If the selected bucket counts add up to all 8 candidate positions, constructive fill can populate the entire candidate before the normal weighted generator runs.

In that case:

  • the candidate is driven almost entirely by the monthly bucket counts,
  • the generator randomly chooses within each eligible bucket, and
  • later weighting systems do not get a chance to choose additional numbers because there are no free slots left.

However, the finished candidate is still checked against later hard rules such as:

  • n-ending terminal digit count rules
  • Single digit / two digit share
  • Odd/Even ratio
  • Last-draw overlap rule
  • Entropy / Hamming / Jaccard

So even a fully constructive candidate can still be rejected and retried.

Ending Digit Sequence Analyzer

The Within-Draw Ending Digit Sequence Analyzer checks whether the numbers in each draw form consecutive circular sequence motifs. It works on the last digit of each number, not the full number itself. Cross-draw same-family runs are measured separately in the Terminal Structure Transition Lab.

Example: 12, 23, 34, 45 has endings 2, 3, 4, 5, so it contains a run of 2-3-4-5. Endings are treated circularly, so 8-9-0 and 9-0-1-2 also count as consecutive runs.

The Recent draws / all separate runs table now exposes every maximal run of at least two terminal digits, not only the longest. For example, 10,21,32,43,5,16,27,37 contains 0-1-2-3 and 5-6-7; both appear in All separate runs, while the four-digit run remains the strongest. This is an illustrative selection, not a recorded result. Sub-runs are not separately counted. Generation controls for exact whole runs are in Terminal Run Quotas, under Signals → Draw Composition Quotas.

Each summary chip is shown as count · percentage. The percentage is based on the current analyzed window only. If the panel's Include supp (main + supp) checkbox is changed, these values can change because the analysis switches between main-only and main+supp numbers.

Run length vs covered numbers

Run length measures the number of distinct consecutive ending digits in the sequence. Covered numbers measures how many actual drawn numbers fall inside that strongest sequence.

Example: if a draw has endings 2, 2, 3, 4, 5, 8, the strongest run is still 2-3-4-5 with run length 4, but it covers 5 numbers because two numbers end in 2. That is why Covered ≥ 4 can be higher than Run ≥ 4.

A quick plain-English reading of the panel is: how often moderate ending-digit runs appear, how often long runs appear, and how much of each draw is explained by the strongest run.

Recent and half-life controls

Recent chooses the newest draw window used for recent shape and hot/cold evidence when Rank ending candidates is pressed. Half-life controls how quickly older evidence fades inside that ranking. Its choices are 3, 6, 9, 12, 24, 36, and WFMQYH.

Simple example: with a half-life of 12, the latest draw receives full recency weight, a draw 12 places back receives half weight, a draw 24 places back receives one-quarter weight, a draw 36 places back receives one-eighth weight, and a draw 48 places back receives one-sixteenth weight. A smaller half-life reacts more strongly to recent movement but can be noisier. A larger half-life changes more slowly and remembers more history.

When does old evidence become zero? It does not have a hard cut-off. Windfall uses weight = 2^(-age / half-life), so each additional half-life halves the remaining weight: 50%, 25%, 12.5%, 6.25%, and so on. After ten half-lives the weight is below 0.1%, which is negligible in practice but is not intentionally set to zero.

WFMQYH as the half-life: this uses the number of active WFMQYH draws as the half-life value. If the active window contains 24 draws, the oldest draw in that window retains approximately half weight. Draws outside the active WFMQYH history are unavailable to this ranking rather than faded by the half-life calculation.

Terminal Structure Transition Lab

The Terminal Structure Transition Lab is an observe-only real-draw audit with three separate views. It does not change candidate generation.

Family and motif are not interchangeable. A terminal family is one fixed ending, such as 2, representing 2, 12, 22, 32, 42. A sequence motif is an overlapping circular set of distinct families, such as 1-2-3 or 8-9-0. Treating the whole motif as one large family would make continuation look artificially easy.
  • Family runs: a family is seeded when one draw contains two or more numbers with that ending. It becomes a confirmed run only if at least one number from that family appears in the immediately following real draw. A gap ends the run. A later seed starts a new potential run.
  • Exact motifs: a motif is present only when the draw contains every ending in the motif. For example, 1-2-3 requires at least one ending-1 number, one ending-2 number, and one ending-3 number. It carries only when that complete motif appears again in the next draw.
  • Motif movement: tests exact carry, a circular shift of minus one, a circular shift of plus one, expansion by one adjacent edge, and contraction by one adjacent edge. These outcomes may overlap and are not competing probabilities.

Example: if one draw contains motif 6-7-8 and the next contains 7-8-9, that is a Shift +1. If 0-1-2 is followed by 9-0-1, that is a Shift -1. Neither is an exact carry.

Observed is the response rate in the selected real historical source. Exact baseline is calculated from the 6/45 or 8/45 combination matrix while correcting for endings 1-5 having five available numbers and endings 0, 6, 7, 8, 9 having four. It is not a simulated draw. Lift is observed rate minus exact baseline in percentage points.

All baseline uses complete real calendar months and excludes incomplete months. WFMQYH uses only consecutive scheduled draw pairs available inside the active history window. The latest current-month state is anchored to the full real history so a shortened WFMQYH window cannot silently relabel a mid-month draw as D1.

The current family state deliberately distinguishes Seed awaiting next draw from Confirmed run. A 2+ family in the latest draw cannot confirm itself; only a later real draw can do that. Invalid dates, duplicate dates, malformed rows, and simulated fallback rows are not used as evidence.

Motifs overlap. For example, 1-2-3 overlaps 2-3-4. Family events are distinct labels, but several can still occur in the same draw transition. The rows therefore are not independent trials. Approximate intervals and positive lifts are descriptive research evidence and are not corrected for trying several families, motif lengths, or movement types. Any future generation influence requires a frozen, no-lookahead walk-forward replay first.

Terminal Family Leadership & Handover

Inside Ending Digit Sequences, open Terminal Family Leadership & Handover to inspect changing terminal-family leadership, run duration, and drought membership. This section starts closed and is observe-only: it does not select numbers, change quotas, boost generation, or add an independent portfolio vote. It recalculates when real history changes.

TFLH-1 fixes the first inspection rule rather than tuning it to a known winning draw: count each family's hits in the preceding three monthly draws, divide by its fair-share hits, and take the top three families, including exact third-place ties. It always uses mains + supps. Endings 1-5 have five numbers; endings 0, 6, 7, 8, 9 have four. Before D3 there is no assigned leadership group, and leadership restarts at each month boundary.

Index example: ending 7 has four available numbers. Its fair-share count across three draws is 3 × 8 × 4 / 45 = 2.13. Three observed hits give 3 / 2.13 = 1.41x. This means 1.41 times the neutral historical-count expectation, not a 41% chance of winning or a forecast. Ties can produce more than three leaders; no digit is discarded merely to force the group to contain three.

  • Leadership & handover: inspect a month locally. New leader entered the group after the previous recorded draw; Left group no longer qualifies.   • Duration & response: a family run starts with two or more same-ending members in one draw, confirms when that ending appears in the next draw, and ends on a miss. Median, Mean, and Longest observed use confirmed runs with an observed ending inside a completed month. A median can legitimately contain a fraction when the middle two durations differ.

  • Family continuation by elapsed run age: age 1 is an unconfirmed seed; a hit in the next draw confirms it. Age 2 or more is an already-confirmed run. The observed percentage counts subsequent real draws containing that ending, compared with its exact family-size-adjusted random presence baseline.
  • Next-draw response by monthly target ordinal: D7, for example, uses leaders or new entrants known after D6, then counts their numbers in D7. These are different denominators. Rows pool completed month lengths; D13/D14 have fewer eligible months.

Entries on the final draw are omitted because no later draw could test their persistence. Late entries have less time to leave, so this descriptive count is not a calibrated forecast.
  • Drought cross-check: Strict 6+ and Empirical top-eight lists are reconstructed before every tested draw, using only earlier consecutive baseline draws, with a minimum of 24. Both use the same all-prior baseline scope here, not a retrospectively chosen WFMQYH setting. Empirical ranks smoothed hazard and can include shorter droughts. Current-state list ranks are retained; k counts draws missed.

Number-draw opportunity example: if two strict-listed numbers belong to leading families before D7, that creates two opportunities. If one appears in D7, there is one hit. An outcome of 1/2 is not the percentage of draws with a winner. The neutral individual appearance baseline is 8/45 = 17.8%. Red numbers identify Strict evidence and blue numbers identify Empirical evidence; a number in both columns belongs to both lists. Strict only, Empirical only, and Both lists separate overlapping leading-family membership.

History and integrity: aggregate outcomes use completed calendar months containing every scheduled Monday, Wednesday and Friday result. The partial opening month and unfinished or incomplete months are excluded. The current month's complete recorded prefix remains inspectable but is not added to completed-month outcomes. Invalid dates, off-schedule draws, simulated rows, malformed numbers, and every row on an ambiguous duplicate date are excluded. Missing history dates restart drought training; missing monthly stages are not renumbered. A new planning month does not inherit old leaders. Interpretation: early leaders are selected because they started strongly, so later cooling can be ordinary regression toward the neutral rate. A leadership change alone does not prove a predictive handover. Run rows overlap leadership rows, Strict and Empirical can overlap, and several family events share one draw. Do not add them as independent confirmations. Small differences and thin ordinal groups remain exploratory. Generation influence would require a separate frozen, no-lookahead validation and user approval.

How to read the month-stage columns

Example: if terminal digit 2 shows First-N hits as 4 · 3 unique, then numbers ending in 2 appeared four times across the selected early draws, but only three different ending-2 numbers were involved. One of those numbers must therefore have appeared more than once.

It should not be read as "this digit is guaranteed to keep moving." Small sample counts, especially for rare D1 multi-hit cases, need extra caution.
This section is an observe-only diagnostic. It can help you explore whether a terminal digit family that appears strongly in D1 tends to keep moving through monthly buckets, but it is not a calibrated probability or an automatic candidate-generation rule.

Monthly Terminal Digit Stage-Split Diagnostic

The Monthly Terminal Digit Stage-Split Diagnostic tests two deliberately separate questions: when a terminal digit family is quiet during an early block such as D1-D6, what happened in the immediate next draw D7, and what happened across D7 through month end? It is observe-only and does not change candidate generation.

Quiet is not an avoid instruction. It means only that the terminal family finished the selected early block below the chosen size-normalised rule. The same family may rebound in the next draw, stay quiet, or become active later in the month.
  • History source uses either baseline history or the active WFMQYH window. The immediate next-draw replay accepts a real unbroken D1-through-target prefix, while the remainder-of-month test still requires a complete calendar month. A WFMQYH slice that begins part-way through a month is never relabelled as D1.
  • Early block ends moves the split from D3 through D10. If it is D6, the early classification uses D1-D6 and the later test uses D7 through month end.
  • Quiet-family rule: Below expected selects every terminal family whose early result is below its fair-draw expectation.
  • Quiet-family rule: Bottom 3 + ties selects the three lowest normalised terminal families and includes exact ties at the third position.
  • Occurrences counts every matching number. Draw presence counts a terminal family no more than once in each draw, even when several numbers share that ending.
  • Month length can combine all complete months or isolate 12-, 13-, or 14-draw months available in the selected history source.

Late ratio is later observed evidence divided by later theoretical expectation. A value of 1.05x means 5% above expectation in the historical sample; it does not mean a 5% greater chance of winning the next draw. The expectation corrects for terminal digits 1-5 having five available numbers while 0, 6, 7, 8, 9 have four.

Immediate next-draw response uses a strict no-lookahead replay. For a D9 split, each valid historical month prefix is classified using D1-D9 only, and then only its real recorded D10 is scored. The month does not need to be finished before that transition can join the replay. Remainder-of-month response uses the same frozen D1-D9 classification but scores D10 through month end, so this broader test still requires a completed month.

Any quiet family reports how many comparable next draws contained at least one selected terminal family, alongside the theoretical expected count. This rate is often naturally high because a quiet set can cover several of the ten terminal families. Do not treat a high raw hit count as an edge unless the observed/expected ratio, older/newer split, uncertainty interval, and random-subset comparison support the same direction.

Month support shows how many complete months finished above the expected late value. Bootstrap interval repeatedly resamples complete months to show how unstable the measured ratio may be. Random subset check compares the observed quiet-family selection with equally sized random terminal-family selections; its p-value is a diagnostic comparison, not a next-draw probability.

If the selected source contains no valid transition, Windfall shows No comparable next-draw transitions for this setup. If it contains no completed remainder, it separately shows No comparable completed months for the remainder test. Windfall does not substitute 0/0, simulated draws, or fallback results.

Older and Newer divide the eligible complete months chronologically. A result that appears only in the older half is less credible than one that keeps the same direction in both periods.

Current-month inspection applies the selected early rule to the open month only when the loaded dates form an unbroken sequence from D1. It labels selected rows as Early quiet, shows any later progress already recorded, and reports how that same terminal family behaved in the immediate next draw of comparable historical months. The prior-response columns show observed versus expected evidence, the ratio, and draw-presence trials. These are inspection aids, not instructions to force or exclude endings.

Example: if nine draws are recorded and Early block ends is D9, the immediate card is a D9 → D10 replay. A ratio of 1.13x means those historically quiet families produced 13% more D10 evidence than their pool-size expectation in the selected sample. It does not mean every listed family is individually strong, and it is not a 13% win probability.

Candidate Translation × Monthly Draw Summary cross-check

This cross-check places Candidate Translation beside the Stage IDM result from Monthly Draw Summary only when both are describing the same working month, the same target draw, and the same 8-number mains-plus-supplementaries scope.

The two diagnostics do not directly agree or disagree because they measure different things:

  • Candidate Translation asks whether whole numbers from terminal-digit families classified as quiet in D1-Dn appeared in the real Dn+1 draw.
  • Stage IDM asks how many of the next draw's eight numbers would ideally come from each current monthly frequency bucket, based on comparable earlier months at the same stage.

The table therefore reports composition compatibility. Read the three tests

  1. Strong and quiet group response: before each target, identify the groups with the most and fewest prior hits. Keep every exact tie. Compare actual next-draw hits with the fair expectation 8 x tied-pool size / 45. All-group ties are uninformative and excluded from this table only. Positive Excess (pp) on Strong suggests persistence; positive excess on Quiet suggests reversal. Excess is 100 x (total hits / total number-draw opportunities - 8/45), not a calibrated next-draw likelihood. Fair expectations may be fractional.
  2. Next-draw composition accuracy: compare group-frequency expected counts with neutral counts of 8 / group count. Error is the mean squared difference between estimated and actual group counts. Lower error is better; Gain = neutral error minus group error, so positive is better. Compare models within a row, not raw count errors between different groupings.
  3. Number-level forecast comparison: compare equal-chance, individual frequency, individual frequency with stronger neutral pull, group frequency, and a fixed 50/50 individual-plus-group blend. Brier x 1,000 is average squared error across all 45 binary appearance outcomes, multiplied by 1,000 for readability. It is not a hit percentage. Lower loss is better. Positive Gain vs fair or Gain vs individual means less error than that comparator, in the same scaled units. A blend improvement alone may be ordinary smoothing; the stronger-pull individual control helps check that alternative explanation.

Earlier / later splits the tested draws chronologically into two sensitivity halves. Both halves have already occurred: they are not an untouched holdout or independent confirmation. Approximate 95% intervals require at least 30 targets and use a draw-level Newey-West interval with six lags. They account for some serial dependence, not every uncertainty, and are not adjusted for testing multiple groupings, models or windows. An interval crossing zero does not clearly distinguish benefit from harm. No automatic significance or winner label is awarded.

Fixed model assumptions, not invented observations

Let n be training draws, h an individual number's actual hits, H a group's actual hits, K its number count and p0 = 8/45. The individual estimate is (h + 30 x p0) / (n + 30). The group estimate per number is (H/K + 30 x p0) / (n + 30); multiply by K to obtain its group count. The blend averages the two estimates. The stronger-pull control uses 60 rather than 30. These constants are disclosed modelling assumptions, not actual extra draws, simulated results or calibrated probabilities. All 45 appearance estimates sum to eight.

Hot vs Cold Ranking

The Hot vs Cold Ranking panel compares three different ideas that are often mixed together when people say a number is “hot”:

  • Historical frequency — how often the number has appeared across the full loaded history.
  • Recent-window hotness — how often the number has appeared in the last selected number of draws.
  • Recency-weighted hotness — a whole-history score that still favours newer draws more heavily than older draws.

This makes it easier to compare the app’s long-run historical counts with the more recent “hot number” style rankings often shown on lottery websites.

Controls

  • Include supplementary numbers — switches the panel between main-only and main+supp analysis.
  • Recent window — chooses how many of the newest draws are treated as the recent comparison window.
  • Weighted half-life — controls how quickly older draws lose influence in the recency-weighted ranking.
  • Digits — restricts the table to all numbers, one-digit numbers, or two-digit numbers only.

How to interpret the rankings

Shared ranking profile: Include supplementary numbers, Recent window and Weighted half-life are owned by Hot vs Cold and immediately update the Hot/Cold evidence used by Signal Confluence and Portfolio Compression. All three use the same all-real-history source and resolved window values, shown beside the consumer readouts. Choosing WFMQYH uses its active draw count for the relevant ranking control; it does not discard the rest of the full-history comparison. Digits, sorting and table disclosure remain local display choices. New presets and prediction snapshots record the profile; older snapshots without it are not treated as having a known historical profile.

  • A number can rank highly in Historical but not be currently hot.
  • A number can rank highly in Recent even if it is not one of the most frequent numbers overall.
  • Weighted sits between the two — it still uses the whole history, but recent draws matter more.
  • Hot score combines recent-vs-prior change and recency-weighted lift to label numbers as Hot, Warm, Neutral, Cool, or Cold.

Breakdown table column definitions

Every breakdown-table column header is sortable. Click once to sort by that column’s default useful direction; click the same header again to reverse it. Sorting changes only the table display order. It does not change hot/cold scores or candidate generation unless you also use the include/exclude row-selection controls.

  • # — the overall hot rank. A lower number means the number currently looks hotter by the panel’s combined scoring model.
  • Num — the lottery number itself.
  • Type — whether the number is 1-digit (1–9) or 2-digit (10–45). This matches the Digits filter.
  • Status — the label assigned from the hot score: Hot, Warm, Neutral, Cool, or Cold.
  • Hist count — how many loaded draws included that number across the full history currently in the app.
  • Hist rank — the number’s rank when sorted by full-history appearance count. Lower rank means more frequent historically.
  • Recent N — how many times the number appeared in the most recent window, where N is the selected recent-window size (for example, 20 draws).
  • Recent rank — the number’s rank when sorted by recent-window appearances. Lower rank means hotter in the current recent window.
  • Prior rate — the hit rate in the older comparison window before the recent window. This is the baseline used to judge whether the number has sped up or cooled off.
  • Recent Δ — the change between the recent hit rate and the prior hit rate, shown in percentage points. Positive values mean the number is appearing more often recently; negative values mean it is appearing less often recently.
  • Weighted rate — the number’s whole-history hit rate after applying recency weighting, so newer draws count more than older draws.
  • Weighted rank — the number’s rank when sorted by weighted rate. Lower rank means stronger recency-weighted hotness.
  • Hot score — the combined score used to produce the overall hot/cold ordering. It blends recent-vs-prior change with recency-weighted lift, so higher positive values are hotter and lower negative values are colder.

Month-end carry-over

The Month-end carry-over card tests a specific hypothesis: numbers that finish a month undrawn may be more likely to appear early in the next month.

How the analysis is built

  1. For each completed month in the active window, the app builds that month’s month-end undrawn set — the numbers not seen anywhere in that month under the current mode.
  2. It then checks the first 3 draws of the next consecutive month.
  3. If a month-end undrawn number appears in those early next-month draws, it counts as an early carry-over hit.
  4. Non-consecutive month gaps are skipped rather than treated as true carry-over transitions.

What the headline stats mean

  • Transitions — how many consecutive month-to-month boundaries were actually evaluated.
  • Month-end undrawn avg — the average size of the month-end undrawn set across those transitions.
  • Early-next-month hit rate — the share of month-end undrawn instances that were drawn within the first 3 draws of the next month.
  • Baseline — the ordinary per-slot draw rate over those same early-next-month draws.
  • Lift — the early-hit rate divided by baseline. Values above 1.00x suggest the month-end undrawn set was drawn early more often than a random number would be.
  • 95% range — the observed transition-to-transition range for early carry-over hit counts.

How to read the number lists

  • Best-supported early next-month flips — numbers that most often moved from month-end undrawn into an early next-month draw.
  • Most persistent into next month — numbers that tended to remain undrawn even after the month changed.
  • Early-hit timing — shows whether those flips happened more often in draw 1, draw 2, or draw 3 of the next month.
The analysis uses the active window only. If the window starts or ends mid-month, the boundary months may be partial, so full-history windows usually give the cleanest month-end interpretation.

Six draws is used because it is roughly a fortnight at three draws per week. The older pooled empirical hazard view remains available as a toggle for comparison.

The strict view treats a number as "appeared" if it was drawn as either a main or supplementary number. It uses the active WFMQYH window for visible context, but uses full real history to break WFMQYH ties and measure the number's completed drought episodes.

Current forecast and latest draw replay

The compact comparison at the top of the panel deliberately shows two different time positions:

  • Current forecast is recalculated after the latest saved draw and therefore targets the next unsaved draw. Strict numbers are shown in red; Empirical numbers are shown in blue. The text labels remain present so color is never the only source cue.
  • Latest draw replay hides the latest target draw, rebuilds both lists from prior real draws only, and then reports which listed numbers appeared as mains or supplementary numbers. S4 means Strict rank 4 and E2 means Empirical rank 2.

This distinction matters after a new result is saved: a number drawn in the latest result resets to drought length zero, so it may disappear from the Current forecast. That does not erase its pre-draw evidence; the honest place to inspect that evidence is Latest draw replay.

The live Strict ordering still uses full real-history current drought; WFMQYH changes only the Strict table's active-window context column. How the shortlist is calculated

  • Scope: mains + supplementary numbers. This is appearance evidence from the full 45-number draw pool, not main-number-only probability.
  • Baseline: before a draw, a number has an 8 / 45 = 17.8% chance of appearing somewhere in the eight drawn numbers.
  • Strict drought state: the default view includes only numbers whose full-history current drought is at least six draws.
  • Strict ranking: rows are ranked first by full-history current drought, then by how mature that drought is against the number's own completed 6+ drought episodes, then by episode frequency and empirical hazard support.
  • Bucket maturity: uses Windfall baseline history after a 24-draw warm-up. It pools all numbers from matching month-length, draw-ordinal, and month-bucket states. For buckets above 0x, the structural maximum immediately before draw D is D - 1 - bucket count. Reaching that limit is a calendar fact, not proof that the number is due.
  • Independent evidence: Bucket maturity does not use Episodes 6+. Episodes 6+ describes one number's own completed droughts; Bucket maturity compares pooled historical bucket-and-stage states. Keeping them separate prevents the same drought evidence from being counted twice.
  • Empirical hazard mode: after each historical draw, the app records each number's drought length k, then checks whether that number appeared in the next draw.
  • Smoothing: the empirical rate adds two baseline-prior trials to stabilize sparse drought lengths. This avoids overstating rare k values that have only a few observations.

Empirical Hazard Calibration Audit

Empirical Hazard Calibration Audit is a collapsed, observe-only card directly beneath the live drought table. Open Review to test whether a learned smoothing strength remains accurate on later real draws. It never changes candidate generation, the drought shortlist, forced selections, or any saved setup.

The current audit is version DHC-1. It uses the Windfall baseline-history slice and accepts only validated real 6-main-plus-2-supplementary draws. Simulated rows, malformed results, duplicate dates, unparseable dates, and draws on unscheduled weekdays are excluded rather than repaired or replaced.

  1. Keep the first 60 valid draws as training history before scoring begins.
  2. For every later target draw, calculate each candidate smoothing strength using only draws that occurred before that target.
  3. Use the first 30 scored targets to compare the pre-registered strengths. Until those outcomes exist, retain the existing two-trial strength.
  4. Before each subsequent target is revealed, select the strength with the lowest accumulated prior-only Brier error.
  5. Reveal and score the real target draw, then make that outcome available only to later targets.

The compared strengths are neutral 8/45 plus finite prior weights of 0, 1, 2, 5, 10, 20, 45, 90, 180, and 360. A finite strength uses:

(observed hits + strength x 8/45) / (observed trials + strength)

Strength zero is the unsmoothed historical rate. Larger values pull sparse evidence more strongly toward 8/45. Neutral 8/45 ignores drought length completely. If neutral records the lowest walk-forward error, the honest conclusion is that the available history has not justified a finite drought adjustment.

Most Likely NOT Drawn / Exclusion Risk Ledger

Most Likely NOT Drawn is an observe-only Exclusion Risk Ledger with a genuine sequential calibration layer, MLND-C1. The adjusted-risk column is learned from earlier out-of-sample forecasts and their subsequent real results. The original heuristic ranking remains available as a clearly labelled raw comparison. Neither list forces candidate-generation exclusions.

Windfall baseline history: MLND ignores WFMQYH and uses real history after excluding a late-start opening month. The exclusion is determined from the first recorded and first scheduled draw dates, rather than permanently excluding May 2024. Literal all real history and the source CSV retain those rows.

The default scope is mains + supps, because the statement “37 numbers will not be drawn” refers to the eight numbers that appear across the full draw result. Mains-only mode is available for diagnosis, but it answers a different question.

Exclusion comparison budget controls how many numbers enter the original raw comparison set and checks whether calibrated evidence supports that count. A 37-number exclusion budget leaves exactly eight numbers, so it is mathematically equivalent to proposing an eight-number draw universe. Changing the budget does not retrain the calibration, select numbers elsewhere or alter generation. Raw comparison pills preserve the original raw ranking; their position is not a calibrated rank.

Fair-draw reference: walk-forward validation trains only on draws before the test draw, then compares raw false exclusions with the exact expectation for a same-size random exclusion set. No random or synthetic draw outcomes are generated. For example, 37-of-45 exclusions against an eight-ball result are expected to wrongly exclude 37 × 8 ÷ 45 = 6.58 drawn numbers. Lower false-exclusion counts are better. Raw, adjusted and neutral Brier scores use the same later target draws.

How the correction learns

The raw model first receives the selected Min training count of earlier real baseline draws (default 60). Its next forecasts are saved with the actual results only after those target draws arrive. After 30 earlier scored forecasts, a monotone calibration map can be fitted. The next target is forecast with that map before its outcome is allowed to update the map. Later forecasts therefore test the correction on outcomes it did not see during fitting. Appending a new draw does not revise the forecasts recorded for earlier targets under the same model version and unchanged source history.

Fixed method: raw indices are grouped into five bands: under 10, 10 to under 20, 20 to under 30, 30 to under 40, and 40 to 100 on the raw 0-100 scale. Weighted pool-adjacent-violators fitting combines adjacent bands when their observed rates contradict the monotone order. Each band has a declared neutral prior weight of 45 to reduce thin-sample overreaction; that is mathematical regularisation, not 45 real or simulated observations. A common log-odds offset then makes the 45 adjusted risks sum to eight (or six for mains only), without using the identities of the next drawn numbers. This is a bounded version of isotonic probability calibration.

Simulated, malformed, off-schedule, future and ambiguous duplicate-date rows are excluded from this calibration. Missing scheduled draws reset both training and calibration, because the app cannot assume the missing results. The opening partial-month baseline policy remains unchanged. WFMQYH is not a training control here.

Reading the audit

  • Later evaluation draws: only targets forecast after the correction had 30 earlier out-of-sample forecasts. These counts are smaller than the raw model's initial walk-forward sample.
  • Raw Brier, Adjusted Brier, Neutral Brier: squared forecast error, averaged across the 45 numbers and target draws. Lower is better. Neutral uses the equal-chance reference of 8/45 or 6/45.
  • Reliability by original raw-score band: shows what the raw index said, what the prior-only correction said, and how often those numbers actually appeared in later target draws. Number states are not independent trials: the same target supplies 45 dependent number states. The separate Target draws column makes that distinction visible.
  • Reliability gap: the number-state-weighted absolute difference between adjusted and observed rates across the original raw bands. This is a descriptive check, not proof by itself.
  • Draw-level intervals: approximate six-lag Newey-West 95% intervals compare per-target Brier differences. These are exploratory, unadjusted intervals, not a claim that 45 number states per draw are independent. Earlier and later chronological halves are sensitivity checks, not untouched holdouts.
  • Latest target decisions: records each target date, the end of its training data, the number of earlier calibration forecasts, and the three measured scores. Export calibration audit saves the model version, declared settings, current fit and the complete historical forecast/outcome ledger.

Evidence gates: at least 120 later evaluation draws, positive raw-score improvement in both chronological halves and in the draw-level interval, plus a weighted reliability gap no greater than three percentage points. A calibrated exclusion recommendation requires additional advantage over the neutral reference, support for the chosen exclusion budget, and a boundary that does not split tied adjusted risks. The model can correct confidence without earning a useful exclusion ranking.

Why every number may show 17.8%: the learned monotone map can legitimately become flat. The fixed eight-ball total then gives every number 8/45 = 17.8% adjusted risk (13.3% for mains only). This is not a fabricated learned distinction or a new prediction: it means the model has no supported risk separation. The app shows None supported for calibrated exclusions rather than breaking the tie by number, raw score or randomness and calling it evidence. Raw comparison sets remain inspectable but are not recommendations.

Integrity note: MLND-C1 was designed after inspecting existing history. Its historical sequential replay prevents target leakage but is not independent prospective confirmation of the design. Subsequent real draws continue the audit. Calibration is not clairvoyance, a guarantee of absence, or a promise of better winning-number selection. The separate Legacy MLND model sandbox in Validation tests older heuristic/logistic predictors, not this ledger; this panel's sequential audit is the authoritative check for MLND-C1.

How to fill in a journal entry

For a new user, the most important rule is simple: fill in only the prediction fields you genuinely want to test. The form is intentionally flexible. You do not need to complete every field, and a notes-only entry is valid if the observation is qualitative.

When you type or paste values into Numbers, Windfall auto-fills derived fields from those listed numbers: terminal digits, odd/even ratio when the listed count matches the target window, current bucket-origin counts, single/double digit counts, exact sum range when the listed count matches the target window, U/D/F ratio, latest-draw repeat count, ±1/±2 neighbour count, strict 6+ drought count, and active month-end carry-over count. These are convenience calculations from the listed numbers and current real-history state; they are not separate predictions.

If you manually edit an auto-filled field, Windfall leaves that manual value alone on later number edits unless you clear the field. This lets you use the autofill as a starting point without losing your own judgement.

  1. Check the anchor latest draw. This is the latest real draw currently loaded. The entry is saved as a prediction made after that draw.
  2. Choose the review status. Use Not reviewed for a draft or quick capture. Use Reviewed by user after you have checked that the entry reflects your actual prediction.
  3. Choose the target window. Use Next draw for a single immediate prediction, Next 2 draws or Next 3 draws for a short sequence idea, or Rest of current month for a month-stage hypothesis.
  4. Add the clearest prediction first. Examples: Odd/even ratio 2:6, Numbers 7, 14, 22, 31, Terminal digits 1, 4, 9, Confidence 65.
  5. Add a selection reason when useful. Example: choose Used ± to choose main 6 if the numbers came from the Latest Draw ±1/±2 Constraint Builder, choose Used DGA constellation diagnostic if the selection came from a measured local diagonal/orbit pattern, choose Used Stage-Match Acceptance Playbook if the bucket mix came from an applied playbook row, or choose Other and type a short reason. The reason is structured data; Notes is the readable copy.
  6. Use target draw bucket-origin mix when your prediction is about where the drawn balls will come from. Example for Next draw: Undrawn 3, 1x 4, 2x 1 means you expect 3 of the 8 drawn balls to come from numbers currently undrawn this month, 4 from numbers currently drawn once, and 1 from numbers currently drawn twice. Do not enter the whole monthly bucket state here.
  7. Use shape checks for broad composition ideas. Example: Single-digit 1, Double-digit 7, Sum min 150, Sum max 210.
  8. Use recorded diagnostics for specific pattern ideas. Example: U/D/F ratio 3/2/3, Repeat count 1, ±1/±2 count 2, Drought count 1, Carry-over count 0.
  9. Add notes while the reasoning is fresh. Example: "Testing whether SDE1 plus HC3 looks stronger on D3 after a low-repeat previous draw."
  10. Save before the target draw arrives. Once the relevant real draw appears in history, the entry locks so it cannot be rewritten after the result is known.
Helpful habit: saving at least one prediction entry per draw gives the app creators a clean audit trail. Saving more than one entry is even better when each entry tests a different idea, such as ratio, candidate numbers, monthly buckets, carry-over, or ±1/±2 behaviour. Over time, this record can help refine Windfall's algorithms and improve its possible winning-entry logic without relying on memory or hindsight.

  • When you save an entry, it is anchored to the latest real draw currently loaded in history.
  • The app also captures the current State Preset-style setup snapshot, including WFMQYH, generation controls, hard filters, selected ratios, selected/excluded numbers, and other preset-managed switches.
  • You can edit or delete the entry while no target draw has arrived yet.
  • If you edit an entry before it locks, the setup snapshot is refreshed to the app state at the time of the latest save.
  • Once the first target draw appears in history, the entry locks and can no longer be edited. This prevents after-the-fact changes.

  • The panel uses real draw history for scoring, not the active WFMQYH filter. WFMQYH can help you form a prediction, but validation must use the actual next draw stream.

Prediction Journal Findings Report

The Prediction Journal Findings Report (PJFR) is an observe-only collective read of saved scorecards. It looks for repeated habits in reviewed, scored entries, such as repeatedly using the same WFMQYH window, same selected ratio, same bucket-mix idea, or same setup provenance. It does not influence candidate generation, ranking, filters, forced inclusions, or forced exclusions.

By default, PJFR uses only entries marked Reviewed by user and already scored against real target draws. Entries marked Not reviewed, pending/unscored entries, and archived entries are excluded from the active read unless you choose to show archived entries.

  • Eligible entries is the count of reviewed scored entries currently used by the report.
  • Scored checks counts hit, partial, and miss scorecard fields. Recorded-only fields are stored for review but do not affect the PJFR support number.
  • Weighted support is a diagnostic score where a hit counts as 1, a partial counts as 0.5, and a miss counts as 0. It is not a lottery probability.
  • Repeated weak setup means the same setup or prediction trait has appeared several times and mostly produced miss outcomes.
  • Worth watching means a repeated trait has scored better than the journal's current overall record. It is a review prompt only, not proof of a predictive edge.
  • Neighbour Atlas usage audit totals frozen reviewed snapshots, completed neutral replays, observed cloud hits versus the exact random expectation cloud size × draw size / 45, and hits among Atlas-cloud numbers the user actually selected. Because journal capture is voluntary, this is a selection-biased usage audit, not the Atlas training source.
Evolution note: PJFR is versioned so future releases can add new finding families without rewriting older journal entries. Treat V1 as a judge of recorded habits, not as a generation engine.

Terminal digit history in saved entries

If a saved entry includes Terminal digits, the expanded journal entry shows a Terminal digit history card. This is a recorded-history check, not a next-draw probability.

  • Contained hits counts historical real draws where every saved terminal digit appeared somewhere in the same draw using mains + supps. The draw may have contained additional terminal digits.
  • Exact set hits counts historical real draws where the draw's unique terminal-digit set matched the saved set exactly.
  • Same-length rank compares the saved set with other terminal-digit sets of the same size, so a three-digit set is compared with other three-digit sets rather than with one-digit or eight-digit sets.
  • Never seen means no valid recorded real draw contained all of those terminal digits together in the selected mains + supps history check.

The card may label a set as common, seen, rare, or never seen. These labels describe historical frequency only; they do not claim the set is due, likely, or guaranteed.

Historical prize collision check

Windfall separates an actual saved-line Division 1/2 match from historical winning numbers covered across several games. Checks use valid real Monday, Wednesday and Friday draw rows, excluding simulated, malformed and duplicate-date rows. A saved entry is checked only through its original anchor draw, so later results cannot become supposed pre-entry historical matches.

  • Individual games: each complete six-number game is checked independently. Six actual mains is Division 1; five actual mains plus an actual supplementary number among the six is Division 2.
  • Historical winning numbers covered across multiple games: the combined pool covers six mains, or at least five mains plus a supplementary number, but no individual game has a D1/D2 match for that draw. The disclosure lists the covered mains and supps and the contributing games. Repeated numbers count once. This is coverage only, not a prize.
  • General Numbers field: the stored-line check uses the first six numbers and the next two supplementary-role numbers when present. A six-number line uses the ordinary played-game prize check. The separate combined selected-pool check ignores line boundaries and is labelled coverage, not a played-game prize. Use Paste Games to preserve separate games.
  • No historical D1/D2 saved-line match found means no saved-line match was found in the eligible history, not that the numbers cannot win in a future draw.

An actual stored-line D1/D2 match in the general hypothesis form asks you to review or save anyway. Combined-pool coverage alone does not trigger that confirmation. Larger pools naturally cover more numbers; neither coverage nor a historical match establishes rarity or a predictive advantage.

Research Diary & Draw Reminders

The Research Diary & Draw Reminders panel is an observe-only note system for recurring ideas. It can remind you that a saved observation may be relevant to the next draw's context, but it does not influence candidate generation, candidate ranking, filters, forced numbers, or scoring.

Use it for recurring setup notes: examples include "check SDE1 and HC3 on D3", "review Wednesday draw behaviour", or "watch month-end carry-over during 13-draw months". Use the Prediction Journal for one-off predictions that need post-draw scoring.

How reminders are matched

  • The panel calculates the next Monday / Wednesday / Friday draw date from the calendar and real draw history.
  • It labels the next draw by month ordinal, for example D1, D2, or D3.
  • Diary notes can be targeted by draw ordinal, weekday, month phase, and scheduled draw count for the month.
  • Rule tags such as SDE1, HC3, Stage IDM, Carry-over, Odd/even, Drought, Hot/cold, and Window shape help you scan notes quickly. Tags do not apply app settings. On a fresh diary note, SDE1 and HC3 tags can be prefilled from the current setup so you do not forget which switches were ON; you can still untick them before saving.

SDE1 + HC3 contextual backtest

The diary also shows a compact SDE1 + HC3 ordinal backtest. The table groups historical trials by draw number within the month. Each trial uses only prior draw history, then asks whether the real target draw contained any number that SDE1 or HC3 would have excluded.

  • Avoided is the observed share of trials where the real draw contained none of the SDE1 + HC3 excluded numbers.
  • Baseline is the random-size expectation for avoiding the excluded set, adjusted for how many numbers were excluded in that trial.
  • Lift is observed avoidance minus the baseline. Positive lift is supportive; negative lift is cautionary.
  • Blocked/draw counts how many real drawn numbers, on average, would have been blocked by SDE1 + HC3.
  • Vs baseline compares expected blocked numbers to observed blocked numbers. Positive values mean fewer real numbers were blocked than the random-size baseline expected.

This backtest can produce stronger early-month advice if D1-D3 rows have enough trials and beat the baseline, but the panel remains observe-only. It does not turn SDE1 or HC3 on for you.

Saved setup provenance

When a diary note is saved, the panel can store a compact snapshot of the current setup, including WFMQYH, generation influence, carry-over state, acceptance-needs state, core SDE1/HC3 switches, selected ratios, and selected/excluded number counts. This is historical context only. It helps you understand what you were looking at when the note was written.

Previous ±1/±2 Neighbour Diagnostics

The Previous ±1/±2 Neighbour Diagnostics panel tests whether a draw tends to include numbers that are one or two steps above or below numbers from the preceding draw. The panel itself is an observe-only diagnostic and does not alter candidate generation; the separate default-off Latest Draw ±1/±2 Constraint Builder in Candidate Generation Influences is where you can deliberately force selected adjacent target numbers into generation.

How the neighbour set is built

For each number in the previous draw, the app creates up to four nearby targets: n - 2, n - 1, n + 1, and n + 2. Boundary numbers produce fewer targets, so 1 can produce 2 and 3, while 45 can produce 44 and 43.

If more than one previous-draw source or offset nominates the same target, that target is marked as a duplicated / ambiguous neighbour; in short, a duplicated neighbour. For example, previous numbers 33 and 35 both nominate 34. A number can also count in more than one directional bucket if it is, for example, +1 from one source and -1 from another.

What the panel reports

  • Neighbour Count & Shape Atlas is the comprehensive count, direction, monthly-stage, odd/even and digit-width diagnostic. Every view is calculated from one auditable transition ledger so different summaries cannot silently use a different ordering or definition.
  • Count & stage shows the complete zero-to-eight unique-hit distribution and a D1-to-D14 matrix. Each matrix cell reports how many historical draws had that exact unique-hit count and its share within that draw ordinal. Avg cloud reports how many of the 45 numbers were eligible on average and the corresponding field-coverage percentage.
  • Direction records each transition as a directional fingerprint, such as -2:2 -1:3 +1:3 +2:2, then reports the most repeated shapes and the leading shape at each monthly draw ordinal.
  • Composition compares odd with even and one-digit with two-digit observed hits. It reports observed, expected and lift so the 23/22 parity split and the much larger 9/36 digit-width imbalance are not mistaken for predictive strength.
  • Transition ledger lists every source-to-target transition newest first, including stage, target-cloud size, unique hits versus expected, directional shape, actual hit numbers, parity and digit width.
  • Current planning cloud shows the latest history-only eligible cloud and same-ordinal historical evidence. It is labelled No future result used because the target result is not known or consulted.
  • Immediate next-draw translation lists every currently eligible number produced from the frozen source draw or draws. Blue numbers have one source path; gold numbers are duplicated / ambiguous targets. The list is exhaustive for the chosen scope and lookback but deliberately unranked. Clicking a number is an explicit shared User Selected Numbers action; the Atlas never selects it automatically.
  • Same-stage count guide translates the highlighted ordinal row into the most frequently observed exact hit counts. It estimates how many members of the cloud appeared historically, not which members will appear next and not a quota or guarantee.
  • Cloud-size-controlled draw-stage evidence separates historical transitions into fixed three-number cloud bands such as 20-22, 23-25, and 26-28. It compares observed hits with each draw's exact random expectation and reports a draw-level 95% excess-hit interval. An interval crossing zero means the neighbour effect remains unresolved after accounting for coverage.
  • Avg unique vs random compares the average count of unique next-draw numbers found inside the neighbour target cloud with the random expectation for the available target count.
  • Duplicated / ambiguous targets highlight numbers reached from more than one source or offset. These are useful selection-inspection clues, not proof of future appearance.
  • Live hand-off read + latest ±1/±2 targets displays the current clean hand-off comparison, such as 81 / 267 / 2, as hit-side wins / miss-side wins / ties. The same card also shows the newest draw's -2, -1, +1, and +2 target cloud for immediate inspection. Those target numbers are selectable; clicking one updates the shared User Selected Numbers state everywhere in the app.
  • Hit vs missed neighbour hand-off test uses each three-draw chain A → B → C. First it builds A's ±1/±2 cloud, then splits that cloud into numbers that hit in B and numbers that missed B. It then treats both groups as fresh ±1/±2 sources and checks which side better explains C. The clean exclusive comparison is the fairer read because it ignores C targets that both sides could claim.
  • Current missed-side helper turns that hand-off idea into a live inspection aid. It uses only the latest two real draws: the previous draw creates an old ±1/±2 cloud, the latest draw splits that cloud into hit numbers and missed numbers, and then the missed numbers receive fresh ±1/±2 treatment for next-draw planning.
  • Soft-rule candidate check samples candidate pools and asks whether candidates ranked by historical neighbour-shape fit score better than random candidates.

How to read the Count & Shape Atlas

  • All baseline is the default. It uses Windfall's real baseline history and excludes target draws from the documented incomplete opening month. The final draw of that excluded month may remain only as source context for the following month's D1 transition.
  • WFMQYH recalculates the atlas from the active WFMQYH slice. This is useful for sensitivity inspection, but a short slice can produce thin or unstable ordinal rows.
  • Broad means at least 20 transitions support that ordinal, Limited means 10-19, and Thin means fewer than 10. These labels describe sample support, not whether the result is favourable.
  • Unique hits count each actual drawn target number once. Directional paths retain every -2, -1, +1 and +2 relationship. One hit can have multiple paths, so path totals may legitimately exceed unique-hit totals.
  • Expected is recalculated from the actual eligible cloud for every historical transition. It is not a fixed 50/50 assumption and it is not simulated result data.
  • Lift is observed divided by expected. A value near 1.000x means the class behaved about as expected; above or below 1.000x should still be read alongside trials and sample quality.
  • Field coverage matters: a cloud covering 25 of 45 numbers already has an expected eight-number hit count of 8 x 25 / 45 = 4.44. Read the observed-versus-expected difference and the coverage-controlled interval rather than treating a high raw ≥3 rate as predictive success.

Shared Atlas references

The Atlas publishes one read-only evidence snapshot so other panels can reference the same definitions without recomputing or exaggerating the signal.

  • Selection Insights shows an Atlas context card for selected anchors. It does not change companion rankings.
  • Signal Confluence uses the Atlas planning cloud in the existing latest-neighbour family. It replaces the older latest-draw neighbour mention instead of counting both; draw-stage lift and sample size add no score.
  • Prediction Journal freezes the pre-draw snapshot and later records a neutral replay against the first real target draw. The replay is audit evidence, not a scored prediction.
  • Active Setup Summary exposes the exact Atlas source, scope, lookback, planning stage, cloud size and sample label as observe-only provenance.
  • Monthly Draws Summary compares the Atlas draw-ordinal evidence only when both panels target the same ordinal. A mismatch is disclosed and comparison is withheld.
  • Latest Draw ±1/±2 Constraint Builder shows the Atlas as a separate reference card. The builder remains user-directed; Atlas evidence never selects a constraint target.
  • Generated Candidates and Trace report candidate coverage of the current cloud after generation. Coverage is an audit observation and does not feed back into construction, filtering, or rank.
  • DGA grid offers a default-off visual overlay for current Atlas targets in the synthetic Next column only.
  • PJFR aggregates saved Atlas replay and usage totals separately from scored prediction fields. Voluntary journal entries never replace the automatic history replay that supports the Atlas itself.
Observe-only boundary: the shared Atlas bridge does not change candidate sampling, ranking, quotas, filters, forced inclusions or exclusions. Thin samples remain visibly labelled and never create a boost.

Hand-off caution: the missed side often contains more source numbers, so raw miss-side hits can look stronger just because that side covers more of the 1-45 field. Read the exposure-adjusted rates, clean exclusive comparison, and sign-test p-value before treating the pattern as useful evidence.

How to use the live hand-off card: read the three numbers as hit-side wins / miss-side wins / ties, then look at the latest-draw target cloud underneath. If the miss-side result remains materially stronger, the cloud gives you a practical list of numbers to inspect or carry into other selection tools. Clicking a target selects or deselects it in the shared user-selected number set, so DGA strips and other user-selection surfaces update together. The hand-off evidence remains diagnostic; generation is affected only through the normal settings that already use User Selected Numbers.

How to use the missed-side helper: start with the missed sources to treat, then inspect the fresh -2, -1, +1, and +2 target lists. Duplicated / ambiguous targets are useful visual clues because more than one missed source points to them. The helper is observe-only; it does not force generation unless you manually select or use those numbers elsewhere.

Latest Draw ±1/±2 Learning & Self-Audit

LDN-SA-1 is the collapsed, observe-only audit inside this panel. It progressively adds one scored row whenever another valid scheduled real draw is loaded. It does not become self-aware, rewrite its own rules, switch the live ±1/±1/±2 mode, or alter candidate generation.

  • Exact live-screen replay means each historical target draw is hidden while Windfall rebuilds the same recent-streak, drought, monthly bucket, terminal-family and month-end screens used by the live Latest Draw rule. The target is revealed only after the eligible list is frozen.
  • Equal-size random is the fair reference. A 20-number target list will naturally collect more hits than a 10-number list, so every row is compared with a random list containing the same number of targets.
  • Excess hits means observed hits minus that equal-size random expectation. It is an audit measurement, not a promised number of future hits.
  • Mode comparison compares screened ±1 and screened ±1/±2 using their size-adjusted excess hits. Windfall keeps mode selection manual unless one mode clears both the paired uncertainty gate and its own random-reference gate.
  • Eligibility screens compares the screened list with the raw neighbour cloud. A negative screen result is a repair warning; it does not silently remove or rewrite the live screen.
  • Current history-only target read shows the present eligible and screened-out numbers without temporary user exclusions. Past user settings cannot be reconstructed honestly, so they are never invented for the replay.

The conservative gates require at least 60 active walk-forward targets and a serial-adjusted approximate 95% interval that excludes no effect. The per-target hit rate and exact at-least-one random reference must also agree before the audit labels lift as validated. Until then, read No validated lift or No validated preference literally.

Advanced soft-rule replay settings

The Warm-up pairs, Candidate pool, and Selected per draw controls are intentionally tucked into an advanced collapsed section. They only tune the older observe-only replay that compares random candidate samples with a neighbour-shape soft ranking. They do not change the Neighbour Count & Shape Atlas and they do not alter candidate generation.

  • Warm-up pairs is the number of historical transitions used for calibration before a target draw is tested.
  • Candidate pool is how many random candidates are sampled for each historical target draw.
  • Selected per draw is how many candidates are retained from that pool for the random baseline and soft-rule comparison.

The ±1 History Table is scrollable and lists active WFMQYH transitions newest first, so users can inspect the history without the table taking over the panel.

Generated Candidates columns

  • Prev±2 counts unique candidate numbers that are ±1 or ±2 from the latest active WFMQYH draw.
  • Dup±2 counts candidate numbers that are duplicated or ambiguous ±1/±2 targets.
  • Dir±2 displays the compact directional fingerprint in the order -2/-1/+1/+2. Example: 2/3/3/2 means -2:2, -1:3, +1:3, and +2:2.

Dir±2 in plain terms: if the latest draw included 15, then 13 counts as -2, 14 counts as -1, 16 counts as +1, and 17 counts as +2. The column is different from Prev±2: Prev±2 counts unique candidate numbers, while Dir±2 counts directional relationships. A candidate number can count in more than one direction if it is reachable from multiple latest-draw numbers, so the Dir±2 total can be higher than Prev±2.

Anti-lookahead rule

For each historical target draw, the soft-rule model is calibrated only from transitions that occurred before that target draw. The target draw and all later draws are hidden from the calibration step.

Truthfulness note: a positive result here is diagnostic evidence, not a guarantee. The panel is intentionally separated from generator controls until backtesting shows that the signal improves candidate quality out of sample.

Consecutive Run Monthly Watch

Consecutive Run Monthly Watch is a versioned, observe-only diagnostic for runs of at least three consecutive whole numbers among the six mains plus two supplementary numbers. A draw containing 24, 25, 26 qualifies regardless of the order in which those numbers appear. Terminal-digit sequences are a different concept and are not counted here.

CRMW-1 uses valid scheduled real draws from Windfall baseline history. It rejects simulated, malformed, duplicate-date and off-schedule rows and excludes the documented partial opening month. A month missing an earlier scheduled draw is excluded from affected first-occurrence stages because Windfall cannot know what happened in the gap. The analysis recalculates when another valid real draw is loaded; it does not invent missing draws, rewrite its own rules or learn from a future result.

How to read the watch

  • Current month watch says whether the current planning month has already recorded a run. When one has appeared, later occurrences are recorded as repeats rather than being treated as another first occurrence.
  • Any run at D counts every qualifying draw at that ordinal, including repeat occurrences in months that had an earlier run.
  • First-risk counts only months that reached that ordinal without an earlier qualifying run.
  • First at D is the number of First-risk months whose first run occurred at that draw.
  • Conditional first is First at D / First-risk. Always read the denominator and sample label. For example, 2/3 = 66.7% is interesting but remains a very thin sample.
  • Cumulative by D reports how many comparable months had produced at least one run by that stage.
  • Random cumulative starts with the exact combinatorial probability that an unordered 8-from-45 set contains a run of three or more, then calculates the chance of seeing at least one across D draws. It is an analytic baseline, not simulated draw data.
  • Occurrence ledger lists each month, its first-run ordinal and every observed run so the headline figures remain auditable.

Drought key cross-check

CRMW-DK-1 asks a narrower historical question: when a consecutive run occurred, did that run contain a number from the Strict drought top eight, the Empirical hazard top eight, or either list as those lists existed before the draw? Windfall rebuilds both lists from expanding all-prior real history with a minimum 24-draw warm-up. The target draw is never included in its own shortlist.

  • Observed is the number and share of historical run sequences containing at least one number from that drought list.
  • Coverage is the comparison baseline. For a run of the same length, Windfall tests every possible contiguous starting position from 1 to 45 and measures how many positions the shortlist would touch. A large shortlist can overlap many runs by coverage alone.
  • Lift is Observed minus Coverage in percentage points. Positive lift is a hypothesis worth monitoring, not proof of prediction.
  • Upper-tail is the descriptive chance of the coverage baseline reaching at least the observed count. Multiple runs in one draw are related observations, so this is not presented as a formal independent-trial significance test.
  • Strict only, Empirical only, In both lists and In neither list identify where individual members of the observed runs came from. Empirical evidence is included because it can nominate genuine drought candidates that are absent from Strict.
  • Draw-ordinal drought cross-check exposes the same comparison by monthly draw number. Small ordinal samples, including late-month rows, remain visibly labelled thin or very thin.

The historical user-selected WFMQYH value cannot be reconstructed for each old draw, so this replay deliberately uses expanding all-prior real history for both lists. It does not pretend that a current WFMQYH setting was known in the past.

One evidence family: draw-ordinal rate, first-occurrence survival, cumulative incidence, the D13 view and the drought key cross-check are related summaries of the same consecutive-run occurrences. They must not be counted as independent Signal Confluence votes. Strict and Empirical drought are dependencies used to cross-check the run evidence, not extra votes created by this panel. CRMW-1 does not sample, rank, reject, boost or construct candidates.

A month reaching a late stage without an earlier run does not make a future run mathematically due. The conditional history is retained as a hypothesis to monitor against subsequent real draws. Thin rows remain advisory-only and never create generation influence.

Observed candidate-sample diagnostics (analysis of 71,000 generated candidates)

  • 2x bucket count had the strongest observed association in the internal candidate sample.
  • Nrr showed a monotonic association in that sample, but should be treated as an uncalibrated rarity diagnostic.
  • Conv direction has zero predictive value — positive and negative Conv candidates win at identical rates.

DGA-ASLA-1DGA Auto Supp Learning Audit version 1. A fixed observe-only, known-eight walk-forward comparison of the current supplementary-role method and two conservative challengers. It does not choose the eight draw numbers, change Auto supps, or influence generation.
DGA Auto suppsDiagnostic supplementary-role split for exactly 8 selected DGA strip numbers. The app chooses two suggested supps from supplementary-count evidence and pair tie-breakers, then the Prediction Journal can score that saved pair against the first target draw's actual supps.
DGA temperature badgesObserve-only letters that can be shown inside Monthly Bucket State Heatmap cells. Compact mode uses H/W/N/C for Hot, Warm, Neutral, and Cold. Detailed mode uses the ten Temperature Heatmap letters.
Drought-breakA forced-inclusion source created by selecting numbers from the Drought-break shortlist. The shortlist itself is diagnostic; selected numbers become hard generation inclusions.
Dir±2Generated Candidates column showing the directional previous-neighbour fingerprint in -2/-1/+1/+2 order. Example: 2/3/1/0 means two candidate numbers are exactly 2 below a latest-draw number, three are exactly 1 below, one is exactly 1 above, and none are exactly 2 above. Ambiguous numbers can count in more than one direction, so this is a directional relationship count rather than a unique-number count.
Dup±2Generated Candidates column counting candidate numbers that are duplicated or ambiguous ±1/±2 neighbour targets because more than one latest-draw source or offset points to the same target.
Empirical hazardA drought-return estimate from observed historical drought lengths and next-draw hits, stabilised by shrinkage toward a neutral baseline.
End boostsSoft generation weighting for numbers with selected terminal digits. Boosts influence sampling but do not override hard exclusions.
End limitsHard terminal-digit count rules. Each terminal digit can be Off, At least, Exactly, or At most a selected Count across the full 8-number candidate.
Exact duplicateA repeated history row with the same date and the same main/supplementary numbers.
Exact pair evidenceDGA supplementary-role tie-break evidence for whether a selected pair has historically appeared together as supplementaries.
Exact maximal terminal runA whole circular sequence of consecutive terminal digits, bounded by missing endings. 2-3-4-5 counts once, never as separate 2-3-4 and 3-4-5 runs. 9-0-1 wraps through zero.
TRQ-1Terminal Run Quotas version 1. A default-off main-generator composition rule using exact maximal runs. Historical occurrence rates describe observed draws; allocation shares divide candidates across selected observed runs and are not winning probabilities.
TRQ-2Terminal Run Quotas version 2. Adds all-observed selection and an explicit equal manual allocation basis for testing unobserved runs, without altering or inventing historical counts. Old saved TRQ-1 evidence is not rewritten.
Generated-pool concentrationTrace phrase showing numbers that appear repeatedly across the displayed generated rows. In RwR45/PNUaRW45 this can be caused by quota pressure and is not automatically a strength signal.
GPWFGlobal Pattern Weighted Frequency — a frequency-weighting option that can bias generation toward number weights derived from recent/global pattern evidence.
HC3A default-off hard exclusion rule. When enabled, the app disables and excludes the numbers identified by that rule; check Trace and the active exclusion badges for the actual affected numbers.
H/W/N/CCompact temperature badge labels: Hot, Warm, Neutral, and Cold. These labels are display-only diagnostics unless a separate generator control explicitly says it uses them.
IDMIdeal Draw Match — similarity of a candidate's bucket composition to the active IDM target. The target is a Bucket Mix Combinatorics applied row when present; otherwise it is the Robust Baseline / Ideal Draw composition from Monthly Draws Summary.
KDEKernel Density Estimate — used by OGA Forecast Bias to describe supported low/mid/high OGA regions. It is a diagnostic density estimate, not a probability guarantee.
p-valueIn validation panels, the share of random or permuted benchmark runs that matched or beat the observed result. Lower values are stronger evidence against a pure-random explanation, but still do not guarantee future outcomes.
Random benchmarkA same-size random control used to judge whether an observed shortlist or strategy is better than chance. It is a measuring stick, not a lottery-number generator.
Lambda / λRecency weighting strength. Higher values shift more influence toward newer draws; disabled means no Lambda adjustment is applied.
LD±1Latest neighbour support in ±1-only mode — an experimental generator rule that derives eligible +1/-1 targets from the latest real WFMQYH draw and can require at least one eligible target.
LD±1/±2Latest neighbour support in widened mode — the same automatic rule as LD±1, but using +2/+1/-1/-2 targets from the latest real WFMQYH draw.
LDN-SA-1Latest Draw Neighbour Self-Audit version 1. A fixed, observe-only walk-forward replay of the live ±1 and ±1/±2 eligibility screens. It compares equal-size random expectations, mode differences and screened versus raw target clouds without changing generation.
Latest Draw ±1/±2 Constraint BuilderA manual builder that shows -2, -1, +1, and +2 targets from the latest draw and lets selected targets become exact forced numbers.
Local-only dateA date present in your local history but absent from the pasted/uploaded comparison source. This is informational only unless you verify that the source is complete.
MBTGMonthly Bucket Transition Governor — default-off soft weighting with Auto evidence or manual Light/Normal/Strong strengths, limited to eligible month stages before hard candidate filters run.
MBS gridMonthly Bucket State grid — the DGA lower grid that shows each number's monthly bucket state across the recorded draws in each month.
MLNDMost Likely Not Drawn — observe-only diagnostics for numbers the model ranks as less likely to appear under its tested evidence frame. It is not a guarantee that those numbers will miss.
MRBMonthly Repeat Bias — a soft monthly-bucket weighting system with a budget so bucket boosts do not silently become unlimited force.
MiANMust Include from Acceptance Needs — post-generation filter requiring minimum counts from each bucket.
MoveRank movement between a full-history ranking and the active WFMQYH ranking. Positive and negative movement describe rank drift, not probability.
Move supportMonthly transition context comparing a bucket's smoothed movement rate with the planning-stage average.
NHBNext Hot Blocks — contiguous number-block heat/drift diagnostics and optional block exclusions.
NDEENext-Draw Evidence Ensemble — the observe-only fixed 6+2 evidence ranking and no-lookahead validation panel.
NrrNumber Rarity Rank — how rare a candidate's numbers are within the generated pool.
NTMR-1 / Movement ReplayNumber Trends Movement Replay version 1. An observe-only dated replay of one number's latest-three minus latest-thirteen appearance-rate difference, measured in percentage points. Rebuilds each state from only information available through that draw and compares fixed value bands with subsequent real outcomes. Does not train or influence generation.
NSNumSum Score — percentile rank of the candidate's total number sum against historical draws.
OGAOctagonal Grid Analysis, the legacy name for the shared historical number-group frequency score. Its current formula is not a geometric distance, angle or symmetry measurement. See Historical OGA Distribution.
OGA%OGA percentile rank against the selected reference history. It is more fragile when the reference window is small.
OGA RawThe unnormalised OGA number-group frequency score before percentile conversion.
NDEDNext Draw Empirical Diagnostics, a retired standalone panel. Historical odd/even counts now live in Draw Composition Quotas; the OGA distribution is under Engine & Ranking as an advanced, retrospective view.
NGFA-1Number-Group Frequency Audit, version 1. An observe-only, prior-draw replay of strong/quiet number ranges, group-count forecasts and individual-versus-group forecast error. Its model estimates are not calibrated probabilities and never affect live generation. See Number-Group Frequency Audit.
NGFA-GR1Number-Group Frequency Audit Generator Replay, version 1. A fixed, paired Off/On experiment using 15 groups, the production generator, and real historical outcomes. It has no live generation toggle, journal effect or automatic adoption. See Paired generator replay.
OGA D0–D9 / Preferred OGA score bandsTen historical OGA score intervals used by the optional acceptance bias. Not monthly draw ordinals or terminal digits. Selected positive-weight intervals are authoritative; acceptance weights are not candidate quotas or winning probabilities. See Preferred OGA Score Bands.
OGA TopPost-process count retained by the OGA ranking path when that path is active.
Obs / expObserved rate versus expected random/combinatorial rate. In Bucket Mix Replay, expected is calculated from the exact before-draw combination space.
OverallEqual-weight percentile rank aggregation across visible bucket metrics. It is a descriptive rank, not a probability.
Panel WFMQYH real drawsA local Scoring System Diagnostics preview value. It changes that panel's displayed counts only and does not change global WFMQYH or generation.
pp / percentage pointsThe arithmetic difference between two percentages. For example, 30% minus 20% is +10 percentage points. A trend difference is not a next-draw probability.
P10-P90The range from a distribution's 10th percentile to its 90th percentile. In Movement Replay it describes historical full-window scores using linear interpolation; it is not a confidence interval or a boundary that future values cannot exceed.
PJ&SPrediction Journal & Scorecard — the panel for recording user hypotheses before a draw and scoring them only after real draw results arrive.
PJFRPrediction Journal Findings Report — observe-only aggregate reporting over saved, scored journal entries.
EP-1Evidence Portfolio model version 1 — four fixed experimental 6+2 hypotheses, frozen comparison controls and leave-one-group-out attribution. Scores are diagnostic, not calibrated winning probabilities.
PNUaRW45Pick Numbers Uniformly at Random Without Replacement over 45. In the UI the same mode is toggled by RwR45.
pR, F, pF, <C, C>, tT, W, H, tR, VDetailed Temperature Heatmap letters, ordered coldest to hottest: prehistoric, frozen, permafrost, cold-side, cool-side, temperate, warm, hot, tropical, and volcanic.
PredictedIn Selection Insights, a blended companion-evidence shortlist from Windowed and All History rates. It is not a calibrated prediction.
Prev±2Generated Candidates column counting unique candidate numbers that are ±1 or ±2 from the latest active WFMQYH draw's numbers.
Quota filterA generation mode that uses learned profile percentages as accept/reject quotas. It changes which rows survive; observe-only modes do not.
Quota pressureTrace phrase meaning selected rules force repeated use of a small eligible number set. Example: if a bucket requires 1 number per row and only 1 eligible number exists, that number must appear in every row.
RdyReadiness Score — user-weighted composite of IDM, |Conv|, and OGA.
RecentHitsGenerated Candidates column counting candidate numbers that overlap the most recent active WFMQYH draw.
RecBiasSoft recent-match bias strength. It influences sampling/ranking locally and is separate from hard latest-draw match filters.
RecMinTrace rejection count for candidates that failed the lower-bound part of the Last-draw overlap rule, such as At least 2 or Exactly 2.
RecMaxTrace rejection count for candidates that exceeded the upper-bound part of the Last-draw overlap rule, such as At most 2 or Exactly 2.
repFamiliesTrace rejection count for the Repeated Terminal Digit Families rule. It counts terminal digit families that appear at least twice, using the selected mains-only or mains+supps scope.
RepeatThe repeat-union pool built from numbers seen in the newest W active WFMQYH draws. It is separate from the immediate last-draw-only controls.
RwR45The UI toggle for PNUaRW45 random coverage mode.
Same-date conflictTwo rows that share the same draw date but contain different numbers. Usually indicates a manual-entry or copy/paste mistake.
SDE1A default-off hard exclusion rule. When enabled, the app disables and excludes the numbers identified by that rule; check Trace and the active exclusion badges for the actual affected numbers.
SelHitsHidden Generated Candidates metric counting candidate numbers that overlap user-selected and hard-forced numbers. Retained in CSV export, filters, and optional survivor ranking, not as a visible table column.
SDSRStrict Drought Shortlist Replay — the no-lookahead validation panel used by the SDSR-advised strict drought quota mode.
SGISoft Generation Influence — a weighting layer applied before hard filters. It can nudge sampling, but exclusions, forced inclusions, quotas, and other hard rules still decide what survives.
SSDSum of Squared Deviations — metric used to measure how far a distribution is from the Monthly Draws Summary target.
Stage IDMStage-conditioned Ideal Draw Match — similarity of a candidate's bucket composition to the next-stage ideal composition from comparable same-size months.
Stage moveThe smoothed historical hit rate for numbers that were in the same monthly bucket before the same planning draw stage.
Strict drought 6+Drought-break mode that ranks numbers whose full-history current drought is at least six draws.
Drought Evidence GovernorDefault-off soft weighting for drought shortlist numbers. Auto checks historical support; Manual uses editable family or per-number weights. Bucket selection and the carry-over switch limit which numbers receive its weights. Separate quota controls set hard minimum counts.
Drought quota countsDefault-off generation controls requiring at least a chosen/advised count of candidate numbers to come from strict drought 6+ and/or empirical hazard shortlists. Advised modes are capped at a low-count minimum of 1; manual mode can deliberately test higher counts. They are hard quotas, not probability claims.
Hazard-advisedEmpirical drought quota mode that uses no-lookahead empirical hazard replay evidence to suggest a cautious minimum count when the replay beats an equal-size random baseline enough to justify it.
Numbers diagnostic influenceDefault-off soft construction weighting from the Numbers ranking in Scoring System Diagnostics. It can nudge sampling but does not override hard generator rules.
Support scoreA relative diagnostic score used to rank evidence rows. Unless a panel says otherwise, it is not a calibrated probability.
TraceThe generation log that records active settings, accepted/rejected counts, rejection reasons, and survivor-selection signals for a generation run.
Tricky RuleAn odd/even helper rule that can override manual odd/even ratio selections while it is enabled.
Typical breakIn drought-break analysis, the historical median or typical length at which that number's completed drought episodes ended.
U/D/FUp / Down / Flat — trend-ratio categories comparing number movement over the selected trend lookback. Ratios add to 8 because they use mains plus supplementaries.
Use countsAcceptance Needs mode that uses the bucket counts directly when constructing or checking candidates.
Use selectedAcceptance Needs mode that uses the exact numbers selected in bucket rows, rather than only the bucket counts.
Vs baselineDifference between an observed/smoothed rate and the neutral baseline rate used by that panel.
WFMQYHWeekly / Fortnight / Month / Quarter / Year / History — the active draw-history window selector used by many panels. It chooses the evidence window; it is not itself a candidate constraint.
WindowedUses the active WFMQYH window rather than all loaded real history.
WinScoreMulti-tier diagnostic score (A–D) gated on the 2x bucket count, the strongest observed association in the internal candidate sample.
WinTierThe letter tier behind WinScore. It groups candidate rows by the diagnostic 2x-bucket rule before tiebreakers are applied.
Windfall baseline historyReal all-history evidence with the opening partial month removed where baseline-style calculations would otherwise be skewed.
ZoneA group of 5 consecutive numbers (Zone 1: 1–5, Zone 2: 6–10 … Zone 9: 41–45).
